Free Salesforce Certified Platform App Builder Online Practice Exam

Overview

  1. Platform App Builder is for people who design, build and deploy custom applications on the Salesforce Platform using declarative (point-and-click) tools.
  2. The exam has 60 multiple-choice and multiple-select questions (plus up to 5 unscored) in 105 minutes.
  3. Passing score is 73%. The registration fee is US$200 and a retake is US$100, plus applicable taxes.
  4. Exam questions align to the Summer ‘26 release, including Flow Approval processes, Agentforce and AgentExchange.
  5. The five sections are weighted 18%, 20%, 32%, 17% and 13%, so this test has 60 questions split 11 / 12 / 19 / 10 / 8, with 5 multiple-select questions.
  6. Exam guide for more details.

Domain 1: Salesforce Fundamentals (18%)

A business wants a complex integration that calls an external REST service in real time, transforms large payloads and handles retries with custom logic. What is the best approach?

⬜ Use a validation rule on the object
⬜ Use a roll-up summary field
⬜ Use programmatic code such as Apex
⬜ Use a custom report type

Which requirement can be met declaratively, without code?

⬜ Call a SOAP web service and parse a custom binary response
⬜ Build a custom algorithm that runs across millions of rows nightly
⬜ Show a field on a page only when the record’s Stage is Closed Won
⬜ Create a fully custom UI with complex client-side calculations

A company needs an e-signature solution inside Salesforce and doesn’t want to build one. Where should the app builder look first?

⬜ AgentExchange, for a prebuilt solution
⬜ Setup Audit Trail for a list of installed features
⬜ Schema Builder for a ready-made signature object
⬜ The Developer Console for a sample signature class

The organization-wide default for Opportunity is Private. Sales managers must see all opportunities owned by people below them. What provides this?

⬜ A permission set that grants Read on Opportunity
⬜ Role hierarchy with hierarchy access granted
⬜ A validation rule on the Opportunity object
⬜ A page layout assigned to the managers’ profile

Users with the Sales profile need to edit the Discount field, but a few Sales users must only view it. What is the best way to set this up?

⬜ Read-only in the profile, plus a permission set to edit for the few
⬜ Create a second page layout with the field marked read-only for everyone
⬜ Use a validation rule that blocks every user from saving the field
⬜ Remove the field from all page layouts and reports in the org

Records in a custom Project object are Private by default. All members of the Finance public group must be able to read projects where Region equals EMEA. What should be configured?

⬜ An owner-based sharing rule for each project owner in EMEA
⬜ Manual sharing performed by each record owner
⬜ A change to the organization-wide default to Public Read Only
⬜ A criteria-based sharing rule for EMEA projects

How should organization-wide defaults be set when designing a sharing model?

⬜ Public Read/Write for everything, then restrict with page layouts
⬜ Public Read Only for everything, then remove access with roles
⬜ Most restrictive needed, then open access with sharing tools
⬜ Controlled by Parent for every object, including standalone ones

A manager wants a report that shows accounts with or without related cases. Standard report types don’t offer this combination. What should be created?

⬜ A roll-up summary field on Account that counts cases
⬜ A custom report type, Accounts with or without Cases
⬜ A joined report with only the Accounts block
⬜ A dashboard filter on the Cases report type

Which TWO statements about dashboards are correct? (Choose two.)

⬜ A dashboard component gets its data from a source report
⬜ A dynamic dashboard shows data as the viewing user
⬜ A dashboard must be refreshed manually by an admin every time it’s viewed
⬜ A dashboard can only show data from one report
⬜ A dashboard ignores the security of its running user

A sales director wants opportunity amounts grouped into ranges such as Small, Medium and Large on a report, without creating a new field. What should be used?

⬜ A formula field
⬜ A bucket column
⬜ A roll-up summary
⬜ A row-level formula only

A permission set group grants Delete on Contracts, but one subset of users must not delete contracts. What is the best approach?

⬜ Add a muting permission set to the group to remove Delete
⬜ Remove the Delete permission from the profile of every user
⬜ Create a validation rule that prevents deleting any record

Which field type should be used to store a value that must be unique across records and used to match records during imports from an external system?

⬜ A formula field that concatenates the record name
⬜ A text field marked as an External ID and Unique

⬜ Salesforce Connect with external objects

⬜ They can be created on either side of a lookup relationship

⬜ They can only be created on detail objects in any kind of relationship type
⬜ They can only count records and never sum field values

Before a large import, an admin wants to keep a copy of all org data. What should be used?

⬜ Setup Audit Trail

⬜ The Recycle Bin

⬜ The child object must have no records at all

Domain 3: Business Logic and Process Automation (32%)

Opportunities need a field showing the number of days until the Close Date, updated automatically. What is the simplest solution?

⬜ A record-triggered flow that runs every night
⬜ A roll-up summary field on the Opportunity
⬜ A formula field: CloseDate - TODAY()
⬜ A validation rule that calculates the days

A Case formula field needs to show the Account’s Industry. What kind of formula is this?

⬜ A roll-up summary formula from Account to Case
⬜ A validation rule referencing the Account object
⬜ A lookup filter on the Case’s Account field
⬜ A cross-object formula referencing Account.Industry

Which formula returns TRUE when a picklist field Status__c equals ‘Closed’?

⬜ ISPICKVAL(Status__c, “Closed”)
⬜ Status__c = “Closed”
⬜ CONTAINS(Status__c, “Closed”)
⬜ TEXT(Status__c) = Closed

An Account needs a field showing the total Amount of its Closed Won opportunities. What should the app builder use?

⬜ A roll-up summary on Account with a Closed Won filter
⬜ A formula field on Account that references Opportunity.Amount
⬜ A validation rule on Opportunity that updates the Account
⬜ A cross-object formula on Opportunity that points to Account

Which limitation of roll-up summary fields should an app builder keep in mind?

⬜ They can’t be used on any custom object in the org
⬜ They recalculate only once a week in a batch
⬜ They can only be displayed on reports, not page layouts
⬜ They can’t sum cross-object or NOW() formulas

Users must enter a Discount Reason whenever the Discount is greater than 10%. What should be used?

⬜ A formula field that shows a warning icon
⬜ A required field on the page layout
⬜ A validation rule: AND(Discount__c > 0.1, ISBLANK(Discount_Reason__c))
⬜ A roll-up summary on the parent Account

A validation rule should prevent users from changing an opportunity’s Close Date to a date in the past. Which formula works?

⬜ AND(ISNEW(), CloseDate > TODAY())
⬜ AND(ISCHANGED(CloseDate), CloseDate < TODAY())
⬜ CloseDate = TODAY()
⬜ ISBLANK(CloseDate)

When a case is created with Priority set to High, a task must be created for the account owner immediately. Which automation should be used?

⬜ A screen flow launched from a button
⬜ A schedule-triggered flow that runs weekly
⬜ A validation rule on the Case object
⬜ A record-triggered flow, run after save

A field on the same record must be updated as fast as possible when the record is saved. Which flow type is best?

⬜ A record-triggered flow optimized for actions and related records
⬜ A screen flow embedded on the record page
⬜ An autolaunched flow called from a button
⬜ A before-save (fast field update) record-triggered flow

Service agents need a guided, step-by-step wizard to collect information during a call. Which flow type fits?

⬜ A screen flow
⬜ A schedule-triggered flow
⬜ A record-triggered flow
⬜ A platform event–triggered flow

Every night, contracts that expire within 30 days should be flagged for renewal. Which flow type is best?

⬜ A screen flow
⬜ A schedule-triggered flow
⬜ A before-save record-triggered flow
⬜ A flow launched from a quick action

Discounts over 20% need a manager’s approval, with multiple steps and the ability to add AI or automated steps. Which tool does Salesforce recommend for new approvals?

⬜ A validation rule that emails the manager
⬜ A formula field that marks the record approved
⬜ A Flow Approval Process built in Flow Builder
⬜ A roll-up summary on the parent Account

Which TWO actions help troubleshoot a flow that isn’t behaving as expected? (Choose two.)

⬜ Review the flow error email or fault path details
⬜ Turn off field history tracking on the object
⬜ Add a validation rule to the triggering object
⬜ Run the flow in debug mode in Flow Builder
⬜ Delete the flow and rebuild it from scratch in a new org

A record-triggered flow sometimes fails when an update element errors. How can the flow handle this gracefully?

⬜ Add a decision element at the start of the flow
⬜ Add a fault path that logs or notifies
⬜ Move the flow to run only on record deletion
⬜ Convert the flow to a validation rule

An admin changes an active flow. What happens to the existing version?

⬜ The active version is overwritten immediately with no history
⬜ All earlier versions are deleted automatically
⬜ Saving creates a new version; earlier versions are kept
⬜ The flow stops running until Salesforce Support reviews it

A sales team wants an AI agent to answer employees’ questions about orders and take simple actions such as updating a record. Which capability fits?

⬜ A roll-up summary field on Order
⬜ A custom report type for orders
⬜ A validation rule on the Order object
⬜ Agentforce, with topics and actions such as flows

How can an existing autolaunched flow be used by an Agentforce agent?

⬜ Convert it into a validation rule first
⬜ Add it as an agent action
⬜ Rewrite it as a formula field
⬜ Attach it to a page layout section

Which statement about the order of automation is correct when a record is saved?

⬜ After-save flows always run before validation rules
⬜ Before-save flows run before custom validation rules
⬜ Validation rules run after the record is committed
⬜ Roll-up summaries are calculated before before-save flows

Records of different types of opportunities must follow different sales stages and picklist values. What should be configured?

⬜ Record types with sales processes
⬜ Validation rules for each stage
⬜ Roll-up summary fields per type
⬜ Separate custom objects per type

⬜ Full sandbox
⬜ Developer sandbox
⬜ Developer Pro sandbox
⬜ Scratch org without data

Developers need an inexpensive environment to build and unit test configuration, with no production data. Which sandbox is best?

⬜ Full sandbox
⬜ Partial Copy sandbox
⬜ Developer sandbox
⬜ A copy of production

Which statement about change sets is correct?

⬜ They move records, such as accounts and contacts, between orgs
⬜ They can deploy between any two unrelated Salesforce orgs
⬜ They move metadata between connected orgs
⬜ They can delete components from the target org automatically

A change set deployment fails because a custom field used in a page layout is missing in the target org. What should the admin do?

⬜ Add the dependent field to the change set
⬜ Deploy the page layout alone again without changes
⬜ Delete the page layout in the target org first
⬜ Import the field’s data with Data Loader

An ISV wants to distribute an app on AgentExchange, protect its code and send upgrades to customers. Which package type should it use?

⬜ An unmanaged package
⬜ A change set
⬜ A data export file
⬜ A managed package

A consultant wants to share a sample app template that customers can freely edit after installing, with no upgrades planned. Which option fits?

⬜ A managed package
⬜ A Full sandbox refresh
⬜ An unmanaged package
⬜ A data import

Which TWO practices belong in a good deployment plan? (Choose two.)

⬜ Deploy without listing the components or their dependencies first
⬜ Skip user communication because changes are small

⬜ Make all changes directly in production during business hours

⬜ Salesforce DX with version control and scratch orgs
