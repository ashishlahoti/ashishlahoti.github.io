Comprehensive list of Free Professional Scrum Developer I (PSD I) exam questions, grouped by official exam domain, curated for cracking the exam with confidence.

Disclaimer: Scrum.org and the Scrum Guide are protected brands/works. These exam questions are neither endorsed by nor affiliated with Scrum.org. These are not the official Scrum.org exam questions/dumps. They are created from the PSD I assessment page, the 2020 Scrum Guide and public software engineering references, and every explanation links to its source. Once you go through these questions and their concepts, you are more than ready to crack the exam in first attempt.

Note: PSD I is for developers working in Scrum Teams. Most questions test modern engineering practices rather than the Scrum framework itself.

Overview

  1. The Professional Scrum Developer I (PSD I) assessment from Scrum.org tests how well you build software in a Scrum Team: test-driven development, refactoring, continuous integration, the Definition of Done, emergent design, testing and collaboration.
  2. The assessment has 80 questions in 60 minutes: multiple choice, multiple answer and true/false. It’s online and in English.
  3. The passing score is 85%, and the fee is US$200 per attempt.
  4. About 85% of the questions come from Developing and Delivering Products Professionally; the other 15% cover the Scrum framework, people and teams, and product management.
  5. This test has 80 questions split 68 / 7 / 2 / 3 across the four focus areas, including true/false and multiple-answer questions.
  6. PSD I assessment page for more details.

Domain 1: Developing and Delivering Products Professionally (about 85%)

What is the correct order of steps in test-driven development?

⬜ Write the code, write a test, then refactor
⬜ Write a failing test, make it pass, then refactor
⬜ Refactor, write the code, then write a test
⬜ Write every test for the whole release before writing any production code

What is the main purpose of refactoring?

⬜ To add new features faster
⬜ To rewrite the whole system in a newer language and framework from scratch
⬜ To fix defects reported by users
⬜ To improve the code’s internal structure without changing its behavior

True or False: Refactoring should only be done in a dedicated “refactoring Sprint” at the end of a release.

⬜ False
⬜ True

What is continuous integration?

⬜ Merging all feature branches together once, at the end of each Sprint, before the review
⬜ Hiring developers continuously
⬜ Integrating code into the mainline frequently, with an automated build and tests
⬜ Deploying to production every hour without testing

The CI build breaks after a commit. What should the Developers do?

⬜ Keep committing new work and fix the build at the end of the Sprint
⬜ Fix the build immediately, as the team’s top priority
⬜ Turn off the failing tests
⬜ Wait for the Scrum Master to assign someone

What is the difference between continuous delivery and continuous deployment?

⬜ They are the same practice
⬜ Continuous delivery skips automated tests
⬜ Continuous deployment requires a manual approval from the Product Owner before every single release
⬜ Delivery keeps every change releasable; deployment releases each passing change automatically

What is technical debt?

⬜ The extra future work caused by shortcuts in design or code
⬜ Money owed to software vendors
⬜ The number of open Product Backlog items that are not yet ready for a Sprint
⬜ Hours spent in Scrum events

How should Developers handle known technical debt?

⬜ Hide it so stakeholders aren’t worried
⬜ Ignore it until the product is retired, since fixing it adds no new features
⬜ Make it transparent and pay it down regularly
⬜ Track it only in their personal notes

According to the test pyramid, which kind of tests should a team have the most of?

⬜ Manual exploratory UI tests
⬜ Fast, small unit tests
⬜ End-to-end UI tests
⬜ Performance tests

What do feature toggles allow a team to do?

⬜ Avoid writing any automated tests
⬜ Skip the Definition of Done
⬜ Release features to production without needing any version control or tests
⬜ Merge unfinished features into the mainline while keeping them hidden

What does YAGNI (“You Aren’t Gonna Need It”) advise?

⬜ Don’t build functionality until it is actually needed
⬜ Build every feature you might need in the future so the design never has to change
⬜ Avoid all design work
⬜ Never write tests

What is a benefit of pair programming?

⬜ It halves the number of developers the team needs for the same amount of work
⬜ It removes the need for any tests
⬜ Continuous review and shared knowledge of the code
⬜ Only the senior developer writes code

What is mob (ensemble) programming?

⬜ Each developer works alone on a separate branch and merges at the end of the Sprint
⬜ The whole team works on the same thing, at the same time, at one computer
⬜ Developers compete to finish first
⬜ Only testers write code

What is the format of a behavior-driven development (BDD) scenario?

⬜ Input, process, output
⬜ Plan, do, check, act
⬜ Who, what, where
⬜ Given, When, Then

What is acceptance test-driven development (ATDD)?

⬜ The team agrees acceptance tests with stakeholders before building the item
⬜ Testers write the acceptance tests after the Sprint ends, based on the delivered features
⬜ Only users test the product in production
⬜ Developers skip unit tests

A unit test needs to isolate a class from a slow payment service. What should be used?

⬜ The real payment service in production
⬜ A manual test step
⬜ A test double such as a mock or stub
⬜ No test at all for this class

What does trunk-based development recommend?

⬜ Long-lived feature branches for each feature, merged together at the end of the release
⬜ Committing to a shared trunk often, with short-lived branches if any
⬜ A separate branch for every developer for months
⬜ Never merging to the main branch

Why are long-lived feature branches risky?

⬜ They make code reviews unnecessary
⬜ They speed up continuous integration because each branch is built separately
⬜ They are required by the Scrum Guide
⬜ They delay integration and cause large, risky merges

What does code coverage tell a team?

⬜ Which parts of the code are run by tests
⬜ That the code has no defects
⬜ How many users the product has
⬜ How quickly the code runs under production-like load

True or False: 100% code coverage proves that the software has no defects.

⬜ False
⬜ True

In Scrum, how does architecture usually develop?

⬜ It’s fully designed by an architect before the first Sprint and never changed
⬜ It emerges and evolves over Sprints as the team learns
⬜ It’s designed by the Product Owner
⬜ It’s ignored until the last Sprint

Who decides how to turn Product Backlog items into a Done Increment?

⬜ The Product Owner
⬜ The Scrum Master
⬜ The architects outside the team
⬜ The Developers

What is the purpose of a spike?

⬜ To research or prototype to reduce uncertainty
⬜ To deliver a large feature quickly by skipping the usual Definition of Done
⬜ To skip testing for one item
⬜ To measure team velocity

Which INVEST quality means a Product Backlog item can be completed without depending on others?

⬜ Valuable
⬜ Estimable
⬜ Independent
⬜ Testable

A Product Backlog item is too large to finish in one Sprint. What should the team do during refinement?

⬜ Leave it as is and carry it over
⬜ Split it into smaller items that each deliver value
⬜ Assign it to the most senior developer so it can be finished faster than usual
⬜ Extend the Sprint

What is a vertical slice of functionality?

⬜ Only the database layer of a feature, built completely before any other layer
⬜ Only the user interface mockups
⬜ A list of tasks for one developer
⬜ A thin piece of a feature through all layers, from UI to data

Who is responsible for estimating Product Backlog items?

⬜ The Developers who will do the work
⬜ The Product Owner alone
⬜ The Scrum Master
⬜ The stakeholders

What should the Definition of Done include for a software product?

⬜ Only “code written”
⬜ Only the Product Owner’s approval that the feature looks right at the Sprint Review
⬜ Quality measures such as code review, tests passing and integration
⬜ Nothing; it’s optional

True or False: If the Definition of Done for an Increment is part of the organization’s standards, all Scrum Teams must follow it as a minimum.

⬜ False
⬜ True

Several Scrum Teams work on one product. What must be true of their Definition of Done?

⬜ Each team may have its own different, weaker Definition of Done if it wants
⬜ Only the first team needs a DoD
⬜ DoD doesn’t apply to multiple teams
⬜ They share and comply with the same Definition of Done

A Product Backlog item doesn’t meet the Definition of Done at the end of the Sprint. What happens?

⬜ It returns to the Product Backlog for future consideration
⬜ It’s released anyway, with a warning to users that some parts are incomplete
⬜ The Sprint is extended
⬜ It’s counted as done

What is the purpose of a code review?

⬜ To find out which developer should be held responsible for each defect found
⬜ To replace automated tests
⬜ To improve quality and share knowledge of the code
⬜ To slow down delivery

Which practice helps find defects in legacy code before refactoring it?

⬜ Deleting old code without tests
⬜ Writing characterization tests that capture current behavior
⬜ Rewriting the whole system first
⬜ Waiting for users to report defects in production and then fixing them one by one

Which design principle states that a class should have only one reason to change?

⬜ Open/closed principle
⬜ Liskov substitution principle
⬜ Dependency inversion principle
⬜ Single responsibility principle

What do low coupling and high cohesion lead to?

⬜ Modules that are easier to understand, test and change
⬜ Code that’s harder to change
⬜ More dependencies between modules, so that changes spread across the whole system
⬜ Slower builds

What is the main goal of automating the deployment pipeline?

⬜ To remove the need for a Definition of Done because the pipeline checks everything
⬜ To avoid source control
⬜ To release reliably and repeatably with fast feedback
⬜ To deploy only once a year

Developers find a defect in an item they completed in the current Sprint. What should they do?

⬜ Log it and fix it in a future hardening Sprint
⬜ Fix it as part of meeting the Definition of Done
⬜ Hide it until the Sprint Review
⬜ Ask the Product Owner for a new Sprint

True or False: A “hardening Sprint” to fix accumulated defects before release is a recommended Scrum practice.

⬜ True
⬜ False

What is the main benefit of automated regression tests?

⬜ They quickly confirm existing behavior still works after changes
⬜ They replace the need for a Definition of Done and for any manual exploratory testing
⬜ They make manual testing illegal
⬜ They write production code

Who is responsible for testing in a Scrum Team?

⬜ Only a separate QA department that tests the work after the Developers hand it over
⬜ Only the Product Owner
⬜ All Developers share responsibility for quality
⬜ Only the Scrum Master

What does a cross-functional Scrum Team mean?

⬜ Each member can do every task equally well
⬜ The team has all the skills needed to create value each Sprint
⬜ The team includes people from every department
⬜ Members switch teams every Sprint

A Developer lacks database skills needed for a Sprint goal. What is the best approach?

⬜ Leave the database work for a specialist team outside the Scrum Team to complete later
⬜ Remove the item from the Sprint
⬜ Ask the Scrum Master to do the work
⬜ Collaborate and learn from teammates, for example by pairing

What does self-managing mean for the Developers?

⬜ They decide internally who does what, when and how
⬜ They can change the Sprint Goal on their own whenever the work turns out to be harder
⬜ They don’t need a Product Owner
⬜ They can skip Scrum events

How do Developers plan the work for the Sprint?

⬜ The Scrum Master assigns tasks to each Developer
⬜ The Product Owner writes all tasks
⬜ They create the Sprint Backlog plan and adapt it daily
⬜ Managers approve each task

Which practice gives fast feedback on whether a change works in an environment like production?

⬜ Deploying manually once per quarter
⬜ Automated deployment to a production-like environment with tests
⬜ Reviewing all the code together only at release time, after the final Sprint is complete
⬜ Writing documentation first

What should Developers do when a non-functional requirement, such as response time, applies to all items?

⬜ Ignore it until the last Sprint
⬜ Create one separate item at the end
⬜ Ask users to test it in production
⬜ Include it in the Definition of Done

Which TWO practices support continuous integration? (Select two)

⬜ Committing to the mainline at least daily
⬜ Merging feature branches once per release
⬜ Running an automated build with tests on each commit
⬜ Testing only before release
⬜ Each developer keeping a private build

Which TWO are signs of high technical debt? (Select two)

⬜ Small changes take longer and longer
⬜ Velocity rises steadily with good quality
⬜ Defects increase after each release
⬜ New team members onboard quickly
⬜ Tests run fast and reliably

Which TWO are benefits of test-driven development? (Select two)

⬜ A suite of fast regression tests
⬜ No need for refactoring
⬜ Simpler designs driven by tests
⬜ No need for code reviews
⬜ Faster typing

Which TWO practices improve shared code ownership? (Select two)

⬜ Pair or mob programming
⬜ Assigning each module to one person forever
⬜ Collective code reviews
⬜ Keeping code in private repositories
⬜ Rotating developers out every Sprint

True or False: Developers may add work to the Sprint Backlog during the Sprint as they learn more.

⬜ True
⬜ False

A team finds a better technical approach midway through the Sprint. What should it do?

⬜ Wait until the next Sprint Planning to discuss it, so the current plan stays unchanged
⬜ Ask the stakeholders for permission
⬜ Adapt the Sprint Backlog to use the better approach
⬜ Cancel the Sprint

What is static code analysis used for?

⬜ Running the application under load
⬜ Finding issues in code without running it
⬜ Measuring customer satisfaction
⬜ Deploying to production

Why keep the build fast in continuous integration?

⬜ So the pipeline only needs to run once a day, at night, for the whole team
⬜ So tests can be skipped
⬜ So the server is cheaper
⬜ So developers get quick feedback and keep integrating often

What is the purpose of version control?

⬜ To track changes, collaborate and restore previous versions
⬜ To store only the final release version of the product so it can be shipped to customers
⬜ To replace testing
⬜ To manage the Product Backlog

Which practice helps avoid “it works on my machine” problems?

⬜ Each developer configures their own environment by hand, following a written setup guide
⬜ Testing only on developer laptops
⬜ Defining environments as code and using the same build everywhere
⬜ Skipping integration tests

When is the best time to write unit tests?

⬜ After the release, if time permits, so that features reach users as early as possible
⬜ Together with the code, as part of developing each item
⬜ Only in the last Sprint
⬜ Never; manual testing is enough

What is emergent design?

⬜ Designing the complete architecture before coding starts so it never needs to change
⬜ Copying the design from another product
⬜ Avoiding any design decisions
⬜ Letting the design evolve through small changes and refactoring

What is a good practice for releasing a risky feature to users?

⬜ Release gradually behind a toggle and monitor
⬜ Release to everyone at once without monitoring
⬜ Delay releasing until the product is complete
⬜ Release without tests to save time

What helps Developers understand what “done” means for a specific Product Backlog item?

⬜ The item’s estimate only
⬜ The developer’s job title
⬜ Clear acceptance criteria
⬜ The Sprint length

During refinement, Developers notice an item has unclear requirements. What should they do?

⬜ Guess and start coding
⬜ Discuss it with the Product Owner and stakeholders to clarify
⬜ Remove it from the Product Backlog, since unclear items are not allowed in it
⬜ Ask the Scrum Master to decide

Why is monitoring production systems part of professional development?

⬜ It isn’t; a separate operations team handles everything after the product is released
⬜ It replaces testing
⬜ It’s only for security teams
⬜ It shows how the product behaves and is used, informing improvements

True or False: In Scrum, the Developers can include a dedicated tester as long as the whole team remains accountable for quality.

⬜ True
⬜ False

What is the main goal of DevOps practices?

⬜ To separate development and operations further so each group can focus on its own work
⬜ To remove automated testing
⬜ To deliver value faster and more reliably by uniting dev and ops
⬜ To release only once per year

What is a good unit test?

⬜ Slow and dependent on a shared database
⬜ Fast, isolated, repeatable and focused on one behavior
⬜ Testing many unrelated behaviors at once, so that fewer tests are needed overall in the suite
⬜ Run manually once a month

Which TWO practices help keep the Increment releasable at all times? (Select two)

⬜ A strong Definition of Done
⬜ Leaving integration to the last week
⬜ Continuous integration with automated tests
⬜ Batching all testing at release
⬜ Long-lived feature branches

A test fails randomly without code changes. What is the right response?

⬜ Ignore it because it passes sometimes
⬜ Delete all tests in that area
⬜ Run it repeatedly until it passes
⬜ Investigate and fix the flaky test

What is the role of architecture decisions during a Sprint?

⬜ Developers make and adjust them as needed for the Sprint Goal
⬜ They’re forbidden; the architecture is fixed by architects before the first Sprint begins
⬜ Only the Product Owner makes them
⬜ They’re made only by management

Domain 2: Understanding and Applying the Scrum Framework (part of 15%)

What are the three pillars of empiricism in Scrum?

⬜ Planning, execution, delivery
⬜ Focus, openness, respect
⬜ Transparency, inspection, adaptation
⬜ Roles, events, artifacts

What is the maximum length of a Sprint?

⬜ Two weeks
⬜ One month
⬜ Three months
⬜ It depends on the release date

Who attends the Daily Scrum as required participants?

⬜ The whole organization
⬜ Only the Scrum Master
⬜ Stakeholders and managers
⬜ The Developers

Which commitment is associated with the Increment?

⬜ Definition of Done
⬜ Product Goal
⬜ Sprint Goal
⬜ Velocity

Which are the Scrum values?

⬜ Speed, quality, cost and scope
⬜ Transparency, inspection and adaptation
⬜ Commitment, focus, openness, respect and courage
⬜ Plan, do, check and act

When can an Increment be released?

⬜ Only at the end of the Sprint, after stakeholders approve it during the Sprint Review event
⬜ At any time it meets the Definition of Done and the Product Owner decides
⬜ Only once per release cycle
⬜ Only when all Product Backlog items are done

Who is accountable for ordering the Product Backlog?

⬜ The Developers
⬜ The Scrum Master
⬜ The stakeholders
⬜ The Product Owner

Domain 3: Developing People and Teams (part of 15%)

How does a Scrum Master support the Developers’ growth?

⬜ By coaching them in self-management and cross-functionality
⬜ By assigning tasks to each developer daily
⬜ By making all technical decisions
⬜ By evaluating each developer’s individual performance and reporting it to their managers

What is the purpose of facilitation in Scrum events?

⬜ To decide outcomes for the team
⬜ To report on how each individual contributed, so management can track performance
⬜ To help the team have productive, time-boxed discussions
⬜ To lengthen events

Domain 4: Managing Products with Agility (part of 15%)

How do Developers help with forecasting and release planning?

⬜ By committing to fixed delivery dates for every feature in the Product Backlog up front
⬜ By sizing items and sharing progress data the Product Owner uses to forecast
⬜ By ignoring dates entirely
⬜ By deciding the release scope alone

What is the best measure of progress for a product?

⬜ Lines of code written
⬜ Total hours worked by the team and the number of tasks completed each Sprint
⬜ Number of meetings held
⬜ Valuable, Done Increments delivered to users

Stakeholders want to give feedback on the product. When is the formal opportunity in Scrum?

⬜ The Sprint Review
⬜ The Daily Scrum
⬜ The Sprint Retrospective
⬜ Sprint Planning only
