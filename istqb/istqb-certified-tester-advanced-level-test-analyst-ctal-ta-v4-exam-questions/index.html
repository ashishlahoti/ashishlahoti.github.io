Overview

  1. The ISTQB Certified Tester Advanced Level Test Analyst (CTAL-TA) certification is for experienced testers who design and run business-facing tests: test analysis and design, risk-based testing, black-box and experience-based test techniques, quality characteristics and defect prevention.
  2. You need the ISTQB Certified Tester Foundation Level (CTFL) certificate before you can take it.
  3. The exam has 45 multiple-choice questions in 120 minutes (150 minutes for candidates taking it in a non-native language).
  4. Questions are worth 78 points in total: K2 questions are worth 1 point, K3 “apply” questions 2 points and K4 “analyze” questions 3 points. 51 points (65%) passes.
  5. Questions per chapter follow the official exam structure: 8 / 3 / 22 / 4 / 8. This test uses the same split, with scenario and calculation questions for the K3 and K4 learning objectives.
  6. Exams are run by ISTQB® member boards and exam providers, so the fee depends on your country.
  7. CTAL-TA v4.0 page and syllabus for more details.

Domain 1: The Tasks of the Test Analyst in the Test Process (17.8%)

A team delivers a product in increments, adding features to the same code base every few weeks. Which concern for the test analyst grows most with each increment?

⬜ Regression risk to features delivered in earlier increments
⬜ Writing the complete test basis before the first increment starts
⬜ Running all test execution only once, after the final increment
⬜ Handing test analysis over to developers after the first increment

Which task does the test analyst perform as part of test analysis?

⬜ Preparing input data and running a smoke test of the test environment
⬜ Reviewing the test basis for testability and defining test conditions
⬜ Comparing actual results with expected results and logging the outcome
⬜ Assembling test procedures into test suites and scheduling them for runs

An automated regression test fails overnight on a feature that nobody changed. What should the test analyst do before raising a defect report?

⬜ Raise a critical defect at once, because any failed regression test means a regression
⬜ Delete the test from the suite, because it fails on code that has not changed
⬜ Analyze the anomaly, such as by a manual rerun, to rule out a false positive
⬜ Mark the test as passed, since the feature itself was not part of the change

Which statement about high-level and low-level test cases is correct?

⬜ A low-level test case states only which test condition is covered, without concrete data
⬜ High-level test cases must always be converted into exactly one low-level test case
⬜ Hybrid test cases are not allowed, so every case is either fully abstract or fully concrete
⬜ One high-level test case can be refined into several concrete low-level cases

A single test case checks login, profile update, password change, an address search and logout. When it fails, it takes hours to find which step caused the failure. Which quality criterion for test cases does it violate most?

⬜ Traceable
⬜ Concise
⬜ Feasible
⬜ Correct

A route-planning service returns different but valid routes for the same request, and there is no practical way to compute the optimal route by hand. Which approach is a recognized solution to this test oracle problem?

⬜ Use the output of the same build as the expected result for the next run
⬜ Skip result checks and rely only on code reviews of the routing logic
⬜ Compare the results with an independent pseudo-oracle implementation
⬜ Increase the number of test cases while leaving expected results undefined

A test analyst needs realistic data to test a hospital appointment system. The team wants to copy the production patient database into the test environment. Which test data requirement is most important here?

⬜ Pseudonymize or anonymize the data to comply with privacy regulations
⬜ Use the production data unchanged, because realism is the main requirement
⬜ Avoid invalid data, so that negative tests do not damage the copied records
⬜ Store the data only as CSV, because other formats are not allowed for test data

Account A holds 500 and account B holds 0. Using the keywords below, which test case best checks that a transfer larger than the balance is rejected?

Verify Error Message(text)  Logout()

Which activity is a typical contribution of the test analyst to product risk analysis?

⬜ Defining the overall risk-based test approach and strategy for the whole project
⬜ Proposing mitigations, such as reviews and techniques, for identified risks
⬜ Deciding on behalf of the business which residual product risks will be accepted
⬜ Correcting the code defects that cause the highest-rated risks

An e-commerce team changed the tax calculation used in checkout. Tests are traced to requirements, but there is only time to run about a third of the manual regression suite. Which way of selecting regression tests is best?

⬜ Pick a third of the suite at random so that every area has an equal chance of being run
⬜ Run only the confirmation test for the changed tax rule and skip all other tests
⬜ Impact analysis with traceability for tax and related features, plus the high-risk tests
⬜ Run only the tests that have gone the longest time without being executed

A team selects manual regression tests using coverage-based selection. In the last five cycles, most escaped defects were in checkout flows that rarely change but that most customers use every day. Which adjustment is most appropriate?

⬜ Remove the checkout tests from the suite because the checkout code rarely changes
⬜ Add tests based on operational profiles of frequent, critical usage
⬜ Replace all selection with full regression testing in every single cycle
⬜ Switch to random selection, because no technique is better than another

⬜ It works without a test oracle, because random inputs need no expected results
⬜ It is guided by data semantics, so it finds meaning-related defects

⬜ The Invoice entity is fully covered once all its listed operations are tested
⬜ The missing Delete operation is an anomaly that needs to be investigated
⬜ A defect report is closed, since read-only entities need no further checks

⬜ Search “laptop” again and expect exactly 25 results, as last time

⬜ Filter by brand = Acme; expect at most N results, all in the unfiltered list

⬜ Swapping the start and the destination returns exactly the same distance

⬜ A full list of scripted steps to follow exactly in order
⬜ A statement of what the system must never do, such as double charging
⬜ A rule that testers must not log any questions during the session
⬜ A removal of the timebox so the session can continue until defects are found

Which item is best written for a checklist that supports experience-based testing of web forms?

⬜ Does each mandatory field show an error message when left empty? (Yes/No/N/A)
⬜ Check that the form looks good and feels intuitive to users
⬜ Test all of the error handling on the form thoroughly
⬜ Make sure usability is fine on every browser, device and screen size

Newly hired testers must perform the same concrete input checks on every form, in a set order. Which checklist format fits best?

⬜ A do-confirm checklist that is reviewed only after testing

⬜ A read-do checklist listing the concrete steps or inputs

Which TWO are limitations of crowd testing? (select two)

⬜ It covers fewer devices and environments than an in-house lab
⬜ Data security and confidentiality are harder to protect
⬜ Feedback arrives more slowly than from an in-house team
⬜ Duplicate and false-positive reports add triage effort

⬜ State transition testing with 0-switch coverage of the quote screens

⬜ CRUD testing of the policy and customer entities
⬜ Domain testing for the ranges plus combinatorial testing

⬜ Checklist-based testing by experienced nurses only

Domain 5: Software Defect Prevention (17.8%)

Which TWO activities help the test analyst contribute to defect prevention? (select two)

⬜ Reviewing requirements and models before implementation starts
⬜ Retesting defects after the developers have fixed them
⬜ Taking part in root cause analysis of earlier defects
⬜ Logging failures found during system test execution
⬜ Running the full regression suite before each release

A specification states: orders up to 50 cost 5 to ship; orders over 50 and up to 100 cost 3; orders of 100 or more ship free. The test analyst models the partitions. Which defect does the model reveal?

⬜ There is a gap between 50 and 51
⬜ The second and third partitions overlap at an order value of 100
⬜ There is a gap between 100 and 101
⬜ No defect; the partitions are complete and disjoint

A door controller specification lists: Closed –open–> Open, Open –close–> Closed, Closed –lock–> Locked. The test analyst draws a state model. Which defect does the model reveal?

⬜ The Open state cannot be reached from the initial state
⬜ Two guard conditions on the open event overlap each other
⬜ No transition leaves Locked, so it can’t be unlocked
⬜ The close event has two different target states

Earlier reviews of user stories produced many duplicate findings and missed testability problems. The test analyst wants each reviewer to take a different stakeholder viewpoint and try to write draft acceptance tests. Which review technique is this?

⬜ Ad hoc reviewing without guidance
⬜ Checklist-based reviewing
⬜ Perspective-based reading
⬜ Scenario-based reviewing

Reviewing the use case “Reset password”, a reviewer simulates a user who no longer has access to the registered email address and finds the specification says nothing about this case. Which review technique was applied, and what was found?

⬜ Scenario-based reviewing; a missing exception flow
⬜ Checklist-based reviewing; a wording inconsistency

⬜ Keep the test allocation the same, since Payments still had some defects
⬜ Stop using risk-based testing and spread effort evenly across modules
