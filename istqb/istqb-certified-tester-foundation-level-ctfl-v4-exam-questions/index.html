Overview

  1. CTFL (Certified Tester Foundation Level) is ISTQB®’s entry-level software testing certification and the prerequisite for its advanced and specialist certifications, such as CT-GenAI.
  2. The current exam follows CTFL v4.0, with the syllabus maintained as v4.0.1 (September 2024). There are no prerequisites.
  3. The exam has 40 multiple-choice questions worth 1 point each, in 60 minutes (75 minutes for candidates taking it in a non-native language).
  4. 26 points (65%) passes.
  5. Questions are split across the six chapters as 8 / 6 / 4 / 11 / 9 / 2, with 8 K1 (remember), 24 K2 (understand) and 8 K3 (apply) questions. The K3 questions ask you to apply test techniques, estimation, prioritization and defect reporting. This test follows the same split.
  6. Exams are run by ISTQB® member boards and exam providers, so the fee depends on your country.
  7. CTFL v4.0 page and syllabus for more details.

Domain 1: Fundamentals of Testing (20%)

Which of the following is a typical test objective?

⬜ Proving that the test object contains no remaining defects
⬜ Fixing the defects found so the code becomes correct
⬜ Writing the requirements specification for developers
⬜ Building confidence in quality

A tester finds that an order total is wrong. A developer reproduces the failure, finds the faulty line and corrects it. Which statement is correct?

⬜ The developer’s work is debugging; confirmation testing should follow
⬜ The developer’s work is confirmation testing of the original test
⬜ The tester’s work is debugging, because it revealed the failure
⬜ No further testing is needed once the developer corrects the line

Which statement correctly describes the difference between testing and quality assurance (QA)?

⬜ Testing is product-oriented; QA is process-oriented
⬜ Testing is process-oriented; QA is product-oriented
⬜ Testing and QA are the same activity under two different names
⬜ QA is the responsibility of the test team alone, not of the whole project

A developer misreads a requirement and codes the wrong interest formula. Customers later receive incorrect statements. Which sequence correctly names these events?

⬜ Failure, then defect, then error
⬜ Defect, then error, then failure
⬜ Error, then defect, then failure
⬜ Root cause, then failure, then defect

A regression suite has run unchanged for two years and now rarely finds new defects. Which testing principle does this illustrate?

⬜ Tests wear out
⬜ Defects cluster together
⬜ Exhaustive testing is impossible
⬜ Testing is context dependent

During which test activity are test conditions identified and prioritized, answering the question ‘what to test’?

⬜ Test design
⬜ Test implementation
⬜ Test analysis
⬜ Test execution

A team creates stubs and drivers so that a component can be tested before the rest of the system is ready. In which test activity are these work products typically produced?

⬜ Test planning
⬜ Test implementation
⬜ Test analysis
⬜ Test completion

A company moves all testing to an independent test team in another department. Which risk does the syllabus associate with this level of independence?

⬜ Testers will share the developers’ cognitive biases
⬜ Developers may lose their sense of responsibility for product quality
⬜ Testers will find fewer kinds of defects than developers
⬜ Assumptions made in the specification can no longer be challenged

Domain 2: Testing Throughout the Software Development Lifecycle (15%)

Which statement is a good testing practice regardless of the SDLC model used?

⬜ Test analysis begins only after all of the code has been completed and integrated
⬜ Each development activity has a test activity
⬜ All test levels should share the same test objectives
⬜ Testers review work products only once they’re approved

Which approach writes tests first, then the code to make them pass, and then refactors both?

⬜ Behavior-driven development (BDD)
⬜ Test-driven development (TDD)
⬜ Acceptance test-driven development (ATDD)
⬜ Exploratory testing

Which of the following is an example of shift left?

⬜ Testers review the specification before coding
⬜ Delaying performance testing until the full system is deployed in production
⬜ Running acceptance tests only after the release candidate is ready
⬜ Removing system testing because component tests already exist

An online store’s application is tested together with an external payment service and a shipping provider’s API. Which test level is this?

⬜ Component integration testing
⬜ Component testing
⬜ Acceptance testing
⬜ System integration testing

A defect in the discount calculation was fixed. The team reruns the failing test and also reruns tests of the checkout and invoice features. Which statement is correct?

⬜ Both kinds of rerun are confirmation testing of the fixed defect
⬜ Rerunning the failing test is regression testing; the others are confirmation testing
⬜ The failing test is confirmation; the rest are regression
⬜ Neither is needed, because the developer has already debugged the code

A legacy claims system is being retired, but its data must be kept for ten years. What maintenance testing does the syllabus say may be required?

⬜ Usability testing of the old system’s user interface
⬜ Testing data archiving and later retrieval
⬜ Component testing of every module of the system before it is finally retired
⬜ No testing, because retired systems aren’t maintained

⬜ Using review results to evaluate each participant’s performance
⬜ Reviewing work products in small chunks so reviewers don’t lose focus
⬜ Choosing the most formal review type for every work product
⬜ Giving participants as little preparation time as possible

Which review type is the most formal, follows a defined process, collects metrics, and doesn’t allow the author to act as review leader or scribe?

⬜ Inspection
⬜ Walkthrough
⬜ Technical review
⬜ Informal review

Which statement about static and dynamic testing is correct?

⬜ Static finds defects directly; dynamic triggers failures
⬜ Static testing can only be applied to executable code
⬜ Dynamic testing is better at finding defects in requirements and other non-executable work products
⬜ Static testing is used to measure performance efficiency

Domain 4: Test Analysis and Design (27.5%)

Which statement about black-box test techniques is correct?

⬜ Test cases can only be created after the code has been written
⬜ They are based on an analysis of the test object’s internal structure
⬜ Their effectiveness depends mainly on the tester’s personal experience
⬜ Tests stay valid if the code changes but the behavior doesn’t

A booking form has two fields: membership level (Gold, Silver, None) and payment method (Card, Wallet). Each value is processed differently. What is the minimum number of test cases needed for 100% Each Choice coverage?

⬜ 3
⬜ 2
⬜ 5
⬜ 6

An order quantity field accepts whole numbers from 1 to 100. Which is the minimum set of values that achieves 100% coverage with 2-value boundary value analysis?

⬜ 1, 100
⬜ 0, 1, 2, 99, 100, 101
⬜ 0, 1, 100, 101
⬜ 1, 50, 100

A full limited-entry decision table has three Boolean conditions. One combination of conditions is infeasible. How many test cases are needed for 100% decision table coverage?

⬜ 8
⬜ 6
⬜ 3
⬜ 7

A kiosk has states Idle, CardInserted and Authenticated, and four valid transitions: Idle–insert card→CardInserted; CardInserted–cancel→Idle; CardInserted–correct PIN→Authenticated; Authenticated–eject→Idle. Which single test case, starting in Idle, achieves 100% valid transitions coverage?

⬜ Insert card, correct PIN, eject
⬜ Insert card, cancel, insert card, correct PIN, eject
⬜ Insert card, cancel, insert card, cancel
⬜ Insert card, correct PIN, eject, insert card

Which statement about statement and branch coverage is correct?

⬜ 100% statement coverage guarantees 100% branch coverage
⬜ 100% branch coverage implies 100% statement coverage
⬜ 100% branch coverage guarantees that all defects have been found
⬜ 100% branch coverage guarantees that all defects in the code have been found

What is a weakness of white-box test techniques?

⬜ They can’t be used when the specification is vague or outdated
⬜ They can’t be applied in static testing, such as during code dry runs or reviews of pseudocode
⬜ They give no objective measure of code coverage
⬜ They may miss requirements that were never implemented

A tester works in a 90-minute time box guided by a charter, then discusses findings with stakeholders in a debriefing. Which technique is this?

⬜ Session-based exploratory testing
⬜ Checklist-based testing
⬜ Error guessing with fault attacks
⬜ Acceptance test-driven development

Which guideline about checklists in checklist-based testing is correct?

⬜ Checklists should include items that tools can check automatically
⬜ Checklists should be as long as possible to cover everything
⬜ Checklists should be updated after defect analysis
⬜ Checklist items should be general so testers have freedom

Acceptance criteria for a user story are written as ‘Given a registered user, When they enter a wrong password three times, Then the account is locked’. Which format is this?

⬜ Scenario-oriented
⬜ Rule-oriented
⬜ Use-case-oriented
⬜ Checklist-oriented

A team applies ATDD to the story ‘As a customer, I want to save items to a wishlist so I can buy them later’. After the specification workshop, which test cases should the team create FIRST?

⬜ Negative tests for invalid inputs and error conditions
⬜ Performance tests for the wishlist page under heavy load from many concurrent users
⬜ Tests for features planned in later user stories
⬜ Positive tests of the expected, error-free behavior

Domain 5: Managing the Test Activities (22.5%)

In the test pyramid model, what is true of tests in the top layer compared with the bottom layer?

⬜ They’re faster, more isolated, and more are needed
⬜ They’re smaller and check a tiny piece of functionality
⬜ They’re always component tests run in isolation
⬜ They’re slower and less isolated, so fewer of them are needed

Which statement correctly contrasts entry criteria and exit criteria?

⬜ Entry criteria define when testing ends; exit criteria define when it starts
⬜ Both are set once for the whole project and are never defined separately for each test level
⬜ Entry criteria are preconditions; exit criteria define completion
⬜ Running out of time can never be accepted as an exit criterion

Experts estimate a testing task as optimistic a = 4, most likely m = 10, and pessimistic b = 22 person-days. Using three-point estimation, what is the estimate?

⬜ 12 ± 3 person-days
⬜ 10 ± 6 person-days
⬜ 11 ± 3 person-days
⬜ 11 ± 18 person-days

Test cases have these priorities (1 = highest): TC-A priority 1, TC-B priority 4, TC-C priority 3, TC-D priority 2. TC-A depends on TC-C, which must run first. Which execution order follows the priorities while respecting the dependency?

⬜ TC-A, TC-D, TC-C, TC-B
⬜ TC-D, TC-C, TC-A, TC-B
⬜ TC-C, TC-A, TC-D, TC-B
⬜ TC-A, TC-C, TC-D, TC-B

According to the testing quadrants, which quadrant contains exploratory testing, usability testing and user acceptance testing?

⬜ Q1: technology facing, support the team
⬜ Q2: business facing, support the team
⬜ Q4: technology facing, critique the product
⬜ Q3: business facing, and critiquing the product

Which of the following is a product risk rather than a project risk?

⬜ The test environment may be delivered three weeks later than planned
⬜ Response time may be too slow at peak load
⬜ Key testers may leave the company during the project
⬜ A third-party supplier may go bankrupt before delivery

A test manager needs to inform stakeholders of the deviations from the plan, unmitigated risks, unfixed defects and lessons learned at the end of a test level. Which report fits?

⬜ A test progress report
⬜ A defect report
⬜ A test log for the final cycle
⬜ A test completion report

How does configuration management support testing?

⬜ It versions testware so results can be reproduced
⬜ It decides which test cases should run first, based on the results of the product risk analysis
⬜ It estimates the test effort needed for each iteration
⬜ It replaces the need for defect management

A defect report contains an ID, a title, the test environment, the steps to reproduce, the severity and the priority. Which important information is missing?

⬜ The name of the developer who will fix the defect
⬜ The estimated cost of fixing the defect
⬜ The expected results and the actual results observed
⬜ The root cause of the defect

A team wants to measure which code statements their automated tests exercise. Which type of tool supports this?

⬜ Static testing tools
