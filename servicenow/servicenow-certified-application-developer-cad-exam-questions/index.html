Free ServiceNow Certified Application Developer (CAD) Online Practice Exam

Overview

  1. The ServiceNow Certified Application Developer (CAD) validates the skills to design, build, secure, automate and deploy custom applications on the ServiceNow AI Platform.
  2. The exam has 60 questions (multiple choice and multiple select) in 90 minutes. Multiple-select questions state how many answers to pick, and there’s no partial credit.
  3. ServiceNow doesn’t publish the pass mark (the cut score “is not always 70%”), so this practice test uses 70% as the target.
  4. ServiceNow recommends about six months of hands-on app development experience and the Scripting in ServiceNow Fundamentals and Application Development Fundamentals courses. You keep the certification with annual delta exams.
  5. The six domains are weighted 20%, 20%, 20%, 20%, 10% and 10%, so this test has 60 questions split 12 / 12 / 12 / 12 / 6 / 6, with 6 multiple-select questions.
  6. CAD exam blueprint for more details.

Domain 1: Designing and Creating an Application (20%)

According to ServiceNow’s planning guidance, which application idea is a good fit for the ServiceNow AI Platform?

⬜ Streaming training videos to employees with live audio commentary
⬜ Editing high-resolution product images with custom graphics filters
⬜ Storing unstructured research notes that follow no repeatable process

⬜ A highly customized user interface
⬜ Orchestration of several back-end systems
⬜ Processes that cannot be repeated
⬜ Simple forms feeding task management
⬜ Web and mobile access to the same data

⬜ It is prefixed with sys_ to mark it as a system table
⬜ It gets the app’s namespace identifier as a prefix
⬜ It uses the label exactly as typed, including spaces

What happens when a new table extends an existing base table?

⬜ It copies the base table’s records into the new table
⬜ It inherits all the base table’s fields
⬜ It shares only the base table’s ACLs, not its fields
⬜ It replaces the base table, which becomes read-only

⬜ Extend the Task [task] table

⬜ Extensible
⬜ Auto-number
⬜ Create module
⬜ Allow access to this table via web services

While creating a table, a developer selects Create access controls and enters a value in the User role field. What does the system do?

⬜ Assigns the role to every user in the application scope
⬜ Restricts the application menu to admins until the role is granted
⬜ Creates a group with that name and adds the developer to it
⬜ Creates basic security rules for the table requiring that role

A developer selects Create module while creating a table. What does this option do?

⬜ Creates a script include with CRUD functions for the table
⬜ Creates a form view that hides the system fields
⬜ Packages the table as an installable module for the Store

⬜ Separator

⬜ Any one of the role, condition or script evaluates to true
⬜ Only the script needs to return true; the role is just a label

To read the Cost field on a custom table’s record, which ACLs must the user pass?

⬜ Only the field-level ACL, because it is more specific
⬜ Only the table-level ACL, because fields inherit it
⬜ Every wildcard ACL on the instance, in any order

A user fails the first ACL that matches a record. What does the system do next?

⬜ It denies access without checking any other ACLs
⬜ It checks the next matching ACL in processing order
⬜ It grants access because the table is in a scoped app
⬜ It asks the user to elevate to the security_admin role

⬜ Add the acl_admin role to their user record

⬜ Switch to the Global application scope
⬜ Turn on session debugging for security rules

⬜ ACLs can secure tables but not scripted REST APIs
⬜ An ACL with no role, condition, attribute or script is empty
⬜ Wildcard ACLs are never evaluated for custom tables
⬜ Admins can view and debug ACLs without elevating
⬜ An empty ACL grants access to every single user on the instance

A user can’t see a field and the admin wants to know which ACL rule is hiding it. Which feature shows the ACL results for each field on the form?

⬜ The Script Debugger’s list of active breakpoints
⬜ The response headers in the REST API Explorer
⬜ The flow execution details for the form
⬜ Field-level ACL debugging (bug icons on fields)

⬜ gs.hasRole(‘x_acme_app.manager’)
⬜ gs.getRole(‘x_acme_app.manager’)
⬜ g_form.hasRole(‘x_acme_app.manager’)
⬜ gs.isMemberOf(‘x_acme_app.manager’)

⬜ gs.hasRole(‘Facilities’)
⬜ gs.getUser().isMemberOf(‘Facilities’)
⬜ gs.getUserID() == ‘Facilities’
⬜ gs.isLoggedIn(‘Facilities’)

⬜ It is ignored, because Enforcing turns tracking off

How do application access settings differ from ACLs?

⬜ They replace ACLs entirely in a scoped application
⬜ They only apply to admins and security_admin users
⬜ They control which roles appear in the navigator
⬜ They limit other apps’ access, not users’ access

⬜ The Accessible from field alone, set to This scope only
⬜ An ACL associated with the script include
