Free Microsoft AI-200 Azure AI Cloud Developer Online Practice Exam

Overview

  1. This is an intermediate level certification for developers who build and run the cloud back end of AI apps on Azure.
  2. Passing AI-200 (Developing AI Cloud Solutions on Azure) earns the Microsoft Certified: Azure AI Cloud Developer Associate credential.
  3. It covers containers on Azure Container Registry, App Service, Container Apps and AKS; vector-ready data services (Cosmos DB for NoSQL, Azure Database for PostgreSQL with pgvector and Azure Managed Redis); Service Bus, Event Grid and Azure Functions; and Key Vault, App Configuration, OpenTelemetry and KQL.
  4. Exam duration is 120 minutes; Microsoft usually sets about 40 to 60 questions, and the exam may include interactive components. Cost varies by country/region.
  5. Passing score is 700 (out of 1000).
  6. The four domains are weighted at 20–25%, 30–35%, 20–25% and 20–25%, so this test has 50 questions split 11 / 17 / 11 / 11.
  7. The certification is renewed annually with a free online assessment on Microsoft Learn.
  8. Study Guide and exam page for more details.

Domain 1: Develop containerized solutions on Azure (20–25%)

A developer’s build agent doesn’t have Docker installed. They need to build an image from the Dockerfile in the current folder and push it to the registry contosoacr in one step. Which command should they use?

⬜ az acr login --name contosoacr followed by az acr repository list
⬜ az acr build --registry contosoacr --image rag-api:v1 .
⬜ az acr import --name contosoacr --source rag-api:v1
⬜ docker build -t rag-api:v1 . followed by docker push

Your team’s inference images are built FROM a shared Python base image in Azure Container Registry. Security wants every application image rebuilt automatically whenever that base image gets an OS patch. What should you configure?

⬜ A registry webhook that sends an email to the developers
⬜ A pull request trigger on the application’s Git repository
⬜ An ACR task with a base image update trigger
⬜ A timer trigger that rebuilds the images once a month

You want a single ACR task that builds an API image, runs a test container against it and pushes the image only if the tests pass. What should you create?

⬜ Two separate registries, one for test images and one for release images
⬜ A quick task started with az acr build
⬜ A base image update trigger on the API image
⬜ A multi-step task defined in a YAML file

A containerized app on Azure App Service needs an API key that’s stored in Azure Key Vault. The code reads the key from an environment variable, and you don’t want to change the code. What should you do?

⬜ Enable a managed identity on the app, grant it read access to secrets and set the app setting to @Microsoft.KeyVault(SecretUri=...)
⬜ Add the secret to the Dockerfile as an ENV instruction
⬜ Copy the secret value into a plain app setting and turn on HTTPS Only
⬜ Give the app’s developers the Key Vault Secrets Officer role

A .NET API runs in a custom Linux container on Azure App Service. It reads the configuration key VectorStore:IndexName. How should you name the App Service app setting so the API picks it up?

⬜ CUSTOMCONNSTR_VectorStore_IndexName
⬜ VectorStore__IndexName
⬜ VectorStore:IndexName
⬜ VectorStore.IndexName

In Azure Container Apps, you update the value of a secret that the current revision uses as an environment variable. The running containers still use the old value. What should you do?

⬜ Change the app’s revision mode to multiple
⬜ Delete the secret and create it again with the same name
⬜ Nothing — the new value appears in running containers within a minute
⬜ Restart the existing revision or deploy a new revision

You’re releasing a new version of a chat API on Azure Container Apps. You want 80% of requests to keep going to the current version and 20% to the new one, then shift the rest later. What should you configure?

⬜ Single revision mode, so the new revision gets traffic once it’s ready
⬜ A second Container Apps environment for the new version
⬜ Multiple revision mode, with traffic split 80/20 between the two revisions
⬜ Two scale rules with different maxReplicas values

A Container Apps worker uses an azure-servicebus KEDA scale rule with messageCount set to 5 and maxReplicas set to 8. The queue currently holds 50 messages. How many replicas does the revision scale to?

⬜ 8
⬜ 50
⬜ 5
⬜ 10

You’ve run az aks get-credentials for a new AKS cluster. You have a manifest file with a Deployment and a Service of type LoadBalancer. Which commands deploy the app and show its public IP address?

⬜ az aks create -f app.yaml, then az aks show
⬜ kubectl get nodes, then kubectl get pods -o wide
⬜ kubectl apply -f app.yaml, then kubectl get service
⬜ az acr build -f app.yaml, then az aks browse

Pods in your AKS cluster can’t pull images from your Azure Container Registry. You want AKS to authenticate to the registry without adding imagePullSecrets to every manifest. What should you run?

⬜ az acr login --name <registry> on each node
⬜ az aks update --attach-acr <registry>
⬜ az acr update --admin-enabled true
⬜ kubectl create secret docker-registry in each namespace

A new container app revision never becomes ready, and its console output is empty. You want to watch the platform’s own messages, such as image pull and probe events, live. Which command should you run?

⬜ az containerapp revision list --name api --resource-group rg
⬜ az containerapp logs show --name api --resource-group rg
⬜ az containerapp show --name api --resource-group rg --query properties.configuration
⬜ az containerapp logs show --name api --resource-group rg --type system --follow

Domain 2: Develop AI solutions by using Azure data management services (30–35%)

A chat app on Azure Cosmos DB for NoSQL must always show users their own just-saved messages, but it doesn’t need global ordering across all users. You want the lowest read cost that meets this. Which consistency level should you use?

⬜ Session
⬜ Eventual
⬜ Bounded staleness
⬜ Strong

A write-heavy telemetry container in Azure Cosmos DB uses the default indexing policy. Queries only ever filter on /deviceId and /timestamp. How can you reduce the RU cost of each write?

⬜ Change the account’s consistency level from session to eventual
⬜ Include only /deviceId/? and /timestamp/? in the index and exclude /*
⬜ Add a composite index on every property
⬜ Set the indexing mode to none

A Cosmos DB query uses ORDER BY c.category ASC, c.score DESC and fails because there’s no matching index. What should you add to the indexing policy?

⬜ A range index on /score/? only
⬜ A vector index on /score
⬜ A spatial index on /category
⬜ A composite index on /category ascending and /score descending

A RAG app will store about 2 million 1,536-dimension embeddings in Azure Cosmos DB for NoSQL and needs low-latency similarity search. Which vector index type should you use?

⬜ flat
⬜ quantizedFlat
⬜ diskANN
⬜ No vector index — use a range index on the embedding path

You’re writing a similarity search query against a Cosmos DB container that has a vector embedding policy. Which query pattern does Microsoft recommend?

⬜ SELECT TOP 10 c.id FROM c ORDER BY VectorDistance(c.embedding, @queryVector)
⬜ SELECT c.id FROM c ORDER BY c.embedding DESC
⬜ SELECT * FROM c WHERE ARRAY_CONTAINS(c.embedding, @queryVector)
⬜ SELECT * FROM c WHERE c.embedding = @queryVector

One change feed processor instance can’t keep up with the inserts into a Cosmos DB container that feeds an embedding pipeline. How should you scale the processing?

⬜ Start more instances with the same processor name and lease container, each with a unique instance name
⬜ Create a second lease container for each new instance
⬜ Give every instance the same instance name so they share work
⬜ Switch the account to strong consistency

Your change feed processor occasionally hands the same item to the delegate twice, for example after an instance restarts. What should you do?

⬜ Disable automatic lease rebalancing
⬜ Make the delegate idempotent, because the processor guarantees at-least-once delivery
⬜ Set WithStartTime to now every time the processor starts
⬜ Switch the lease container to a different region

You’re choosing a partition key for a Cosmos DB container that stores chat messages for millions of users. Most queries fetch one user’s conversation. Which property is the best partition key?

⬜ /region, which has five possible values
⬜ /createdDate, which is the day the message was written
⬜ /userId
⬜ /messageType, which is either user or assistant

An Azure Functions app creates a new CosmosClient on every request. Under load you see slow responses and connection exhaustion. What does Microsoft recommend?

⬜ Create one client per container
⬜ Switch the client to Gateway mode and keep creating it per request
⬜ Dispose of the client and recreate it after every query
⬜ Use a single CosmosClient instance for the lifetime of the application

Running CREATE EXTENSION vector; on Azure Database for PostgreSQL flexible server fails because the extension isn’t allowed. What should you do first?

⬜ Restart the server in Burstable tier
⬜ Enable the pgbouncer.enabled server parameter
⬜ Add vector to the azure.extensions server parameter
⬜ Install pgvector from source on the server’s VM

You created an index with USING hnsw (embedding vector_l2_ops), but EXPLAIN shows a sequential scan for ORDER BY embedding <=> $1 LIMIT 5. Why?

⬜ The table needs to be vacuumed before any vector index is used
⬜ The <=> operator is cosine distance, so the index needs the vector_cosine_ops operator class
⬜ HNSW indexes only work after you set ivfflat.probes
⬜ HNSW indexes can’t be used with LIMIT

You’re creating a vector index on a PostgreSQL table that’s empty today and will be loaded continuously. You want the best speed-recall trade-off and can accept a slower build. Which index type should you choose?

⬜ IVFFlat, because it needs to be trained on existing data
⬜ A B-tree index on the embedding column
⬜ IVFFlat with lists set to 1
⬜ HNSW

Your IVFFlat index returns results quickly, but recall is too low. Which change improves recall at query time without rebuilding the index?

⬜ Raise ivfflat.probes
⬜ Raise hnsw.ef_search
⬜ Lower ivfflat.probes to 1
⬜ Change the query from <=> to <->

Hundreds of short-lived serverless functions open connections to Azure Database for PostgreSQL flexible server (General Purpose tier), and the server runs short of connections. What’s the simplest built-in fix?

⬜ Enable the built-in PgBouncer and connect on port 6432
⬜ Give each function its own database
⬜ Move the server to the Burstable tier
⬜ Raise the number of vCores without changing the app

Your API uses Azure Managed Redis with the cache-aside pattern for product data. When a product is updated, what should the write path do?

⬜ Leave the cache alone and wait for the item to expire
⬜ Update only the cache and let a background job copy it to the data store
⬜ Update the data store first, then remove the item from the cache
⬜ Remove the item from the cache first, then update the data store

Cached LLM responses in Azure Managed Redis are set to expire after 5 seconds, and the database is being hit almost as hard as it was without a cache. What’s the most likely problem?

⬜ The keys don’t include the user’s name
⬜ The cache uses the least-recently-used eviction policy
⬜ The cache-aside pattern doesn’t work with Redis
⬜ The expiration period is too short for how the data is accessed

You plan to use Azure Managed Redis as a vector store for semantic caching. Which tier should you avoid?

⬜ Memory Optimized
⬜ Flash Optimized
⬜ Compute Optimized
⬜ Balanced

Domain 3: Connect to and consume Azure services (20–25%)

A document-ingestion worker reads from the Service Bus queue ingest. A malformed message failed processing 10 times and is no longer in the queue. Where is it, and how do you read it?

⬜ In the Blob Storage dead-letter container configured on the namespace
⬜ In the dead-letter subqueue ingest/$deadletterqueue; open a receiver with SubQueue.DeadLetter
⬜ It was deleted; Service Bus discards messages after the maximum delivery count
⬜ In a topic called deadletter that Service Bus creates automatically

A Service Bus receiver in PeekLock mode calls an LLM that sometimes takes three minutes. The messages keep getting redelivered to other workers while they’re still being processed. The lock duration is the default. What should you do?

⬜ Call AbandonMessageAsync before starting the LLM call
⬜ Set the lock duration to 30 minutes
⬜ Switch to ReceiveAndDelete mode
⬜ Renew the message lock while processing, or use automatic lock renewal

You add a new subscription to a Service Bus topic and don’t define any rules. Which messages does the subscription receive?

⬜ No messages until you add a SQL filter
⬜ Only messages that have a correlation ID
⬜ Every message sent to the topic
⬜ Only messages sent after the first rule is created

A high-volume topic routes messages to subscriptions by matching the Label and ContentType properties against fixed values. Throughput at the subscriptions is lower than expected. Which change does Microsoft recommend?

⬜ Use correlation filters instead of SQL filters
⬜ Create a separate namespace for each subscription
⬜ Add an action to every rule
⬜ Replace the filters with SQL filters that use LIKE

An Event Grid subscription on a storage account should trigger an OCR function only when a .pdf blob is created in the invoices container. What filter should you configure?

⬜ No filter — filter the events inside the function code
⬜ includedEventTypes set to Microsoft.Storage.BlobDeleted
⬜ An advanced filter StringContains on data.url with the value pdf
⬜ subjectBeginsWith set to /blobServices/default/containers/invoices/ and subjectEndsWith set to .pdf

An Event Grid webhook endpoint returns HTTP 400 Bad Request for an event, and the subscription has dead-lettering enabled. What happens to the event?

⬜ Event Grid puts it in a Service Bus dead-letter queue
⬜ Event Grid retries it 30 times and then drops it
⬜ Event Grid doesn’t retry and sends it straight to the dead-letter location
⬜ Event Grid retries it with exponential backoff for 24 hours

Your app publishes custom modelRetrained events to an Event Grid custom topic by using an access key. How does the publisher authenticate the HTTP POST?

⬜ It puts the key in the event’s subject field
⬜ It sends the key in the aeg-sas-key request header
⬜ It sends the key as a query string parameter named code
⬜ It signs the event with the topic’s certificate thumbprint

Event Grid delivers events at least once and doesn’t guarantee their order. How should a subscriber that updates a vector index handle this?

⬜ Make processing idempotent, for example by tracking each event’s id
⬜ Return HTTP 400 for any event it has already seen so Event Grid stops retrying
⬜ Turn off retries on the subscription
⬜ Assume events arrive in the order they were published

You’re building a serverless API with Azure Functions. Each HTTP request should also write the request body to a storage queue, without you writing any Storage SDK code. How should you design the function?

⬜ A Timer trigger that polls for HTTP requests
⬜ An HTTP trigger with a Queue Storage output binding
⬜ Two triggers: an HTTP trigger and a Queue Storage trigger
⬜ A Queue Storage trigger with an HTTP output binding

Two functions use the Azure Cosmos DB trigger on the same container and the same lease container: one generates embeddings and one writes an audit log. Only one of them runs when items change. How do you fix it?

⬜ Give each function its own lease container or a different LeaseContainerPrefix
⬜ Enable CreateLeaseContainerIfNotExists on the second function
⬜ Move the functions into separate function apps on the same lease container
⬜ Set StartFromBeginning to true on both functions

A new function app must reach a PostgreSQL server that’s only accessible inside a virtual network, scale to zero when idle and avoid cold starts on its HTTP endpoints. Which hosting choice fits best?

⬜ The Consumption plan with deployment slots for warm-up
⬜ A Windows Flex Consumption app using the C# in-process model
⬜ The Flex Consumption plan with virtual network integration and always ready instances
⬜ The Consumption plan with default settings

Domain 4: Secure, monitor, and troubleshoot Azure solutions (20–25%)

A Container Apps job needs to read an OpenAI API key from Azure Key Vault in code, with no secrets in configuration. Which approach does Microsoft show?

⬜ Download the secret once at build time and bake it into the image
⬜ Use the storage account key to sign a SAS URL for the secret
⬜ Store the vault’s access key in an environment variable and call the REST API
⬜ Create a SecretClient with DefaultAzureCredential and call GetSecretAsync

An App Service app uses a Key Vault reference without a version in the URI. Security rotates the secret. When will the app use the new value if nobody touches the app?

⬜ Only after the app is redeployed
⬜ Immediately, because Key Vault pushes the change to the app
⬜ Within 24 hours, when the cached value is refetched
⬜ Never — versionless references always keep the first version

You want a database password in Key Vault to be rotated automatically before it expires. Which design does Microsoft’s rotation tutorial use?

⬜ Key Vault changes the password on the database server by itself
⬜ An Event Grid subscription to the SecretNearExpiry event that calls a function, which creates a new secret version and updates the database
⬜ An App Configuration sentinel key that triggers a restart
⬜ A Logic App that polls Key Vault every minute for expired secrets

A container app uses a Key Vault reference to the latest version of a secret (no version in the URI), and the secret is rotated. What happens?

⬜ Container Apps retrieves the latest version within 30 minutes, and active revisions that use it in an environment variable restart automatically
⬜ A new revision is created every time the secret changes
⬜ The app gets the new value on the next HTTP request
⬜ Nothing until you add the version to the URI

An ASP.NET Core app loads settings from Azure App Configuration with ConfigureRefresh(o => o.RegisterAll()), but changed values never reach the app. Which two things are most likely missing?

⬜ A shorter cache expiration on the Key Vault reference
⬜ A Key Vault reference and a restart of the app
⬜ A feature flag and a label filter
⬜ The app.UseAzureAppConfiguration() middleware, and reading values through IOptionsSnapshot<T> instead of IOptions<T>

A team keeps model endpoints, feature flags and database passwords together in Azure App Configuration. What does Microsoft recommend?

⬜ Move everything, including feature flags, into Key Vault
⬜ Keep settings and feature flags in App Configuration and store secrets in Azure Key Vault
⬜ Keep everything in App Configuration, because its values are encrypted
⬜ Store the passwords as App Configuration labels

You’re adding OpenTelemetry-based Application Insights monitoring to a production API. Where does Microsoft recommend you put the Application Insights connection string?

⬜ In a query string on every request
⬜ In the container image’s labels
⬜ Hard-coded in Program.cs
⬜ In the APPLICATIONINSIGHTS_CONNECTION_STRING environment variable

A RAG API is instrumented with OpenTelemetry and exports to Application Insights. Where are the distributed tracing spans for incoming calls and for outgoing calls to the vector database stored?

⬜ In the requests and dependencies tables
⬜ Both in the traces table
⬜ In the exceptions table, as one row per span
⬜ In the customMetrics table

⬜ AppRequests | where Success == false
⬜ AppDependencies | where success = "false"
⬜ AppDependencies | where Success == false
⬜ dependencies | where success == false

In a Log Analytics workspace, you want to count failed incoming requests to your API for each HTTP result code. Which KQL query should you use?

⬜ AppTraces | where SeverityLevel == 3 | count
⬜ AppRequests | summarize count() by ResultCode
⬜ AppRequests | where Success == false | summarize count() by ResultCode
⬜ AppRequests | project ResultCode | take 100

An AI agent service runs on App Service, Functions and Container Apps. You need to follow one user request across all three services in Application Insights. What’s the recommended approach?

⬜ Send all logs to one storage account
⬜ Instrument each service with the OpenTelemetry distro and export to the same Application Insights resource, so the trace context is propagated
⬜ Write a custom log line with a GUID in each service and search for it by hand
