Comprehensive list of Free Databricks Certified Data Engineer Associate exam questions, grouped by official exam domain, curated for cracking the exam with confidence.

Disclaimer: Databricks is a protected Brand. These exam questions are neither endorsed by nor affiliated with Databricks. These are not the official Databricks exam questions/dumps. These questions are created from the Data Engineer Associate exam guide, the Databricks documentation and the Apache Spark documentation. They cover all seven sections of the exam, and once you go through these questions and their concepts, you are more than ready to crack the exam in first attempt.

Note: The questions follow the exam published May 4, 2026 (guide updated August 6, 2026) and use current product names: Lakeflow Jobs, Lakeflow Connect, Lakeflow pipelines and Declarative Automation Bundles (formerly Databricks Asset Bundles).

Free Databricks Certified Data Engineer Associate Online Practice Exam

Overview

  1. The Databricks Certified Data Engineer Associate validates the ability to ingest, transform, orchestrate and govern data on the Databricks Data Intelligence Platform.
  2. The exam has 45 scored multiple-choice questions plus up to 10 unscored ones, in 90 minutes, and costs US$200. Databricks recommends about six months of hands-on experience.
  3. Databricks doesn’t publish the pass mark; this practice test uses 70% as the target.
  4. The seven sections are weighted 6%, 21%, 22%, 16%, 10%, 10% and 15%, so this test has 45 questions split 3 / 9 / 10 / 7 / 4 / 5 / 7.
  5. Topics include Delta Lake and compute choices, Auto Loader, COPY INTO and Lakeflow Connect, PySpark and SQL transformations and tuning, materialized views, streaming tables and expectations, Lakeflow Jobs triggers and control flow, Git folders and bundles, Spark UI troubleshooting and liquid clustering, and Unity Catalog permissions, row filters, column masks and ABAC.
  6. Exam guide and certification page for more details.

Domain 1: Databricks Intelligence Platform (6%)

A data engineer accidentally overwrote a Delta table yesterday. How can they query or recover the previous data?

⬜ Re-ingest everything from the source; Delta keeps no history
⬜ Use time travel with VERSION AS OF or TIMESTAMP AS OF, or RESTORE TABLE to a previous version
⬜ Read the files from the driver’s local disk
⬜ Use OPTIMIZE to bring back old versions

Which table type does Databricks recommend by default for new Delta tables in Unity Catalog?

⬜ External tables in every case
⬜ Hive metastore tables
⬜ Temporary views
⬜ Unity Catalog managed tables

A team schedules nightly Python ETL jobs and currently runs them on an always-on all-purpose cluster. What does Databricks recommend?

⬜ Run the jobs on serverless compute (or classic jobs compute if custom settings are needed), not all-purpose compute
⬜ Keep using all-purpose compute for all automated jobs
⬜ Run the jobs on a SQL warehouse
⬜ Run the jobs on the driver of a personal cluster

Domain 2: Data Ingestion and Loading (21%)

New JSON files land in cloud storage throughout the day. The team wants each file processed exactly once as it arrives, without tracking which files were loaded. What should it use?

⬜ A daily spark.read of the whole directory
⬜ A manual list of processed file names in a notebook
⬜ Auto Loader (the cloudFiles source) with a checkpoint location
⬜ dbutils.fs.cp to copy files into a table

An Auto Loader stream reads a directory with millions of files, and listing the directory is slow and costly. What does Databricks recommend?

⬜ Switch to COPY INTO with a full reload each run
⬜ Use file notification mode with file events instead of directory listing
⬜ Reduce the number of executors
⬜ Disable the checkpoint

An Auto Loader stream uses the default schema evolution mode. A new column appears in the source files. What happens?

⬜ The new column is silently ignored
⬜ The stream never stops and puts the column in _rescued_data
⬜ The table is dropped and recreated
⬜ The stream stops with an UnknownFieldException after adding the column to the schema, and resumes with the new schema when restarted

A team wants an Auto Loader stream that never fails because of schema changes and keeps any unexpected fields for later review. Which configuration fits?

⬜ cloudFiles.schemaEvolutionMode = rescue, with unexpected data captured in the _rescued_data column
⬜ cloudFiles.schemaEvolutionMode = failOnNewColumns
⬜ cloudFiles.schemaEvolutionMode = none, which keeps all new data
⬜ Delete the schema location before each run

What enables Auto Loader to infer the schema and track its changes over time?

⬜ Setting spark.sql.shuffle.partitions
⬜ Creating a Git folder
⬜ Setting cloudFiles.schemaLocation to a directory where Auto Loader stores the schema
⬜ Using a SQL warehouse

A SQL analyst runs COPY INTO every hour to load files from a cloud storage path. What happens to files that were already loaded in earlier runs?

⬜ They’re loaded again, creating duplicates
⬜ They’re deleted from storage
⬜ They’re skipped, because COPY INTO is idempotent and retriable
⬜ The command fails until they’re moved

For SQL users who need scalable, robust incremental file ingestion beyond COPY INTO, what does Databricks recommend?

⬜ Temporary views
⬜ Exporting to CSV first
⬜ Manual INSERT statements
⬜ Streaming tables

A company wants to ingest Salesforce and Workday data into Unity Catalog with minimal custom code. Which option fits?

⬜ Lakeflow Connect managed connectors
⬜ A custom REST scraper on all-purpose compute
⬜ Auto Loader in directory listing mode
⬜ COPY INTO from the SaaS application

An operational SQL Server database must be replicated into Unity Catalog tables continuously, capturing inserts, updates and deletes. Which option fits?

⬜ A nightly full export to CSV
⬜ A Lakeflow Connect managed database connector using change data capture
⬜ Auto Loader on the database files
⬜ A file arrival trigger

Domain 3: Data Transformation and Modeling (22%)

In the medallion architecture, where should raw records be cleaned, deduplicated and normalized?

⬜ In the silver layer
⬜ In the bronze layer
⬜ In the gold layer
⬜ In the landing files themselves

Two daily extracts may contain the same rows, and the combined result must keep every row, including duplicates. Which operator should be used?

⬜ UNION
⬜ INTERSECT
⬜ UNION ALL
⬜ EXCEPT

A silver table has an items column containing an array of products per order. Analysts need one row per product. Which function should be used?

⬜ approx_count_distinct
⬜ explode
⬜ array_contains
⬜ collect_list

A gold dashboard needs the number of distinct visitors per day over billions of events, and a small error is acceptable for speed. Which function fits?

⬜ count(DISTINCT visitor_id) on a single partition
⬜ explode
⬜ sum
⬜ approx_count_distinct

A large fact table is joined to a 5 MB dimension table, and the join causes a big shuffle. How can the engineer avoid shuffling the large table?

⬜ Increase spark.sql.shuffle.partitions to 10,000
⬜ Set spark.sql.autoBroadcastJoinThreshold to -1
⬜ Convert the dimension to CSV
⬜ Use a broadcast join, which Spark chooses automatically for tables below spark.sql.autoBroadcastJoinThreshold (10 MB by default) or when given a BROADCAST hint

What does spark.sql.shuffle.partitions control?

⬜ The maximum size of a broadcast table
⬜ The number of partitions used when shuffling data for joins or aggregations (200 by default)
⬜ The number of worker nodes
⬜ How long a job may retry

A gold aggregate is expensive to compute and queried by many dashboards. The team wants results stored and refreshed incrementally where possible. What should it create?

⬜ A standard view
⬜ A temporary view
⬜ A materialized view
⬜ A streaming table that reads a static table

Which object is best for incrementally ingesting new rows from an append-only source, so each refresh processes only rows that arrived since the last update?

⬜ A streaming table
⬜ A standard view
⬜ A materialized view over a static snapshot
⬜ A temporary view

A pipeline must remove rows with a null customer_id before writing a silver table, while letting the update continue. Which expectation fits?

⬜ EXPECT (customer_id IS NOT NULL) ON VIOLATION DROP ROW
⬜ EXPECT (customer_id IS NOT NULL) ON VIOLATION FAIL UPDATE
⬜ EXPECT (customer_id IS NOT NULL) with no action
⬜ A CHECK constraint that stops the job

A pipeline expectation is defined with no ON VIOLATION clause. What happens to records that fail it?

⬜ They’re dropped
⬜ The update fails
⬜ They’re written to the target, and the violation is recorded in the pipeline’s metrics
⬜ They’re moved to a quarantine table automatically

Domain 4: Working with Lakeflow Jobs (16%)

A job should run its transformation tasks only when the upstream ingestion task reports that it loaded new rows. Which task type supports this branching?

⬜ A For each task
⬜ An If/else condition task that evaluates a boolean expression
⬜ A file arrival trigger
⬜ A dashboard task

A cleanup task must run after all upstream tasks finish, whether they succeeded or failed. Which Run if setting should it use?

⬜ All succeeded
⬜ At least one succeeded
⬜ None failed
⬜ All done

A notification task should run only if an upstream task fails, and be skipped otherwise. Which Run if setting fits?

⬜ All succeeded
⬜ All done
⬜ At least one failed
⬜ None failed

A job must run the same notebook once for each of 40 country codes, with up to 5 running at a time. Which feature fits?

⬜ 40 separate jobs
⬜ A For each task with the country list as input and concurrency set to 5
⬜ An If/else condition task
⬜ A table update trigger

Partner files arrive at irregular times in a Unity Catalog volume. The processing job should start soon after a file lands, not on a fixed schedule. What should be configured?

⬜ A file arrival trigger on the volume path
⬜ A cron schedule every minute
⬜ A table update trigger on an unrelated table
⬜ A manual run each morning

A gold job should run whenever its source silver tables are updated by other pipelines. Which trigger fits?

⬜ A file arrival trigger on a random folder
⬜ A fixed hourly schedule
⬜ A For each task
⬜ A table update trigger

When is a time-based schedule a better choice than a file arrival or table update trigger?

⬜ When files arrive at random times
⬜ When downstream tables change unpredictably
⬜ When data arrives at predictable times or the business needs results at fixed times
⬜ When the job should run as soon as new data exists

Domain 5: Implementing CI/CD (10%)

A data engineer wants to work on a feature branch of the team’s repository directly in the Databricks workspace and commit changes. What should they use?

⬜ DBFS root
⬜ A SQL warehouse
⬜ Unity Catalog volumes
⬜ Databricks Git folders

A team wants to define its jobs and pipelines as code in YAML and deploy them to dev and prod workspaces with the Databricks CLI. What should it use?

⬜ Declarative Automation Bundles (formerly Databricks Asset Bundles), with databricks bundle validate, deploy and run
⬜ Manual job creation in each workspace
⬜ Notebook widgets
⬜ Cluster policies only

A bundle must use a different catalog name in dev and prod. How should this be handled?

⬜ Copy the whole bundle for each environment
⬜ Declare a custom variable and set different values per target, referencing it as ${var.catalog}
⬜ Hardcode the prod catalog everywhere
⬜ Edit the deployed job by hand after each deploy

In a CI pipeline, a variable value must be passed to a bundle deployment without editing any files. Which options work?

⬜ The –var option on the bundle command, or an environment variable starting with BUNDLE_VAR_
⬜ A notebook widget
⬜ A cluster tag
⬜ A Unity Catalog comment

Domain 6: Troubleshooting, Monitoring, and Optimization (10%)

A team wants to see whether last night’s job run took much longer than usual and which task failed. Where should it look?

⬜ The cluster’s library list
⬜ The Unity Catalog lineage graph only
⬜ DESCRIBE HISTORY on an unrelated table
⬜ The job’s Runs tab matrix view, which shows run history, task statuses and durations

In the Spark UI stage details, the Max task duration is far longer than the 75th percentile. What does this suggest, and what’s one fix?

⬜ Too few drivers; add a second driver
⬜ Disk is full; delete the checkpoint
⬜ Data skew; consider salting the skewed keys or relying on AQE skew join handling
⬜ The cluster is idle; stop it

A stage shows large spill statistics. Which change can help?

⬜ Turn off the Spark UI
⬜ Set spark.sql.shuffle.partitions to auto or use executors with more memory
⬜ Use a smaller driver
⬜ Disable Auto Loader

A partitioned Delta table has small files and slow queries on a high-cardinality column, and query patterns keep changing. What does Databricks recommend?

⬜ Use liquid clustering, whose clustering keys can be changed without rewriting existing data
⬜ Add more partition columns
⬜ Use ZORDER together with liquid clustering
⬜ Convert the table to CSV

A team wants OPTIMIZE, VACUUM and ANALYZE to run automatically on its tables. What does predictive optimization require?

⬜ The tables must be external tables
⬜ The tables must be CSV
⬜ The tables must be Unity Catalog managed tables
⬜ The tables must have no clustering

Domain 7: Governance and Security (15%)

A data engineer drops a Unity Catalog managed table by mistake. What happens to its data?

⬜ The files stay in storage forever
⬜ The data is deleted instantly with no recovery
⬜ The table becomes an external table
⬜ The data files are deleted after the recovery period (7 days by default), and UNDROP TABLE can recover it within that window

An external table points to files the team manages in cloud storage. What happens when the table is dropped?

⬜ The files are deleted immediately
⬜ Only the metadata is removed; the data files stay in cloud storage
⬜ The files are deleted after 7 days
⬜ The files move to the managed storage location

What’s needed to create an external table on a cloud storage path in Unity Catalog?

⬜ Only workspace admin rights
⬜ A personal access token stored in the notebook
⬜ An external location covering the path, plus the CREATE EXTERNAL TABLE privilege on it and USE CATALOG, USE SCHEMA and CREATE TABLE on the parents
⬜ A SQL warehouse in Pro mode

Which SQL statement gives the analysts group read access to the sales.orders table?

⬜ ALLOW READ sales.orders FOR analysts
⬜ SET PERMISSION analysts = SELECT
⬜ REVOKE SELECT ON TABLE sales.orders TO analysts
⬜ GRANT SELECT ON TABLE sales.orders TO analysts

Regional managers should see only rows for their own region in a sales table. Which Unity Catalog feature fits a single table?

⬜ A row filter, a SQL UDF attached with ALTER TABLE … SET ROW FILTER
⬜ A column mask
⬜ A file arrival trigger
⬜ A materialized view refresh

Only the HR group should see full salary values; everyone else should see a masked value. What should be applied to the salary column?

⬜ A row filter
⬜ A column mask with ALTER TABLE … ALTER COLUMN … SET MASK
⬜ A Git folder
⬜ A table update trigger

A company tags sensitive columns, such as PII, across hundreds of tables and wants masking applied consistently everywhere, without table owners overriding it. What should it use?

⬜ A separate column mask written by each table owner
⬜ Unity Catalog ABAC policies based on governed tags, attached at the catalog or schema level
⬜ Dynamic views copied into every schema
⬜ Workspace-local groups only
