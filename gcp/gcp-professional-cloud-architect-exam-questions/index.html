Free Google Cloud Professional Cloud Architect (PCA) Online Practice Exam

Overview

  1. The Professional Cloud Architect certification validates the ability to design, develop and manage secure, scalable, highly available and cost-effective solutions on Google Cloud.
  2. Google recommends 3+ years of industry experience, including 1+ years designing and managing solutions on Google Cloud.
  3. The exam has 50–60 questions (multiple choice and multiple select) in 2 hours, in English and Japanese, and costs US$200.
  4. Each exam includes 2 case studies that make up 20–30% of the questions; you can view them in a split screen during the exam.
  5. Google doesn’t publish the pass mark; this practice test uses 70% as the target.
  6. The six sections are weighted about 25%, 17.5%, 17.5%, 15%, 12.5% and 12.5%, so this test has 50 questions split 13 / 9 / 9 / 7 / 6 / 6, including 12 case-study questions.
  7. The current exam guide uses Google’s latest product names, such as Gemini Enterprise Agent Platform (formerly Vertex AI) and Gemini Cloud Assist.
  8. Professional Cloud Architect certification page for more details.

⬜ Cloud Storage with one object per message
⬜ Bigtable, with a row key that starts with the truck ID followed by the timestamp

Case study: Fernhill Freight. Read the scenario, then answer the question at the end.

Company overview: Fernhill Freight is a European logistics company with 40,000 trucks. Each truck sends a GPS and engine telemetry message every 10 seconds.

Existing environment: A data center in Frankfurt runs a VMware estate, including a dispatch application on an Oracle database. Telemetry is collected in nightly batches, so dispatchers can’t see where trucks are in real time. Developers keep their code in GitHub and deploy with GitHub Actions.

Business requirements:

  • Give dispatchers a live fleet dashboard and predict delivery arrival times with ML.
  • Close the Frankfurt data center within 18 months.
  • Keep all customer data in the EU.
  • Handle the December peak, when traffic grows to about three times normal.

Technical requirements:

  • Ingest telemetry continuously and store it for fast lookups by truck and time.
  • Move the dispatch database to a managed service with minimal downtime.
  • Don’t store long-lived service account keys in GitHub.
