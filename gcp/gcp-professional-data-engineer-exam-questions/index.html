Disclaimer: Google Cloud and Professional Data Engineer are trademarks of Google LLC. These exam questions are neither endorsed by nor affiliated with Google. These are not the official Google Cloud exam questions/dumps. These questions are created from the Professional Data Engineer exam guide and the Google Cloud documentation. They cover all five sections of the Professional Data Engineer exam, and once you go through these questions and their concepts, you are more than ready to crack the exam in first attempt.

Note: The exam guide still uses the product names Dataproc, Cloud Composer, Dataplex and Analytics Hub, so these questions do too. Google has since renamed them Managed Service for Apache Spark, Managed Service for Apache Airflow, Knowledge Catalog and BigQuery sharing; the certification page says the exam will be updated to match.

Free Google Cloud Professional Data Engineer (PDE) Online Practice Exam

Overview

  1. The Professional Data Engineer certification validates that you can design, build, secure, monitor and optimize data processing systems on Google Cloud, from ingestion and storage to analysis, sharing and AI-ready data.
  2. Key services include BigQuery, Dataflow (Apache Beam), Pub/Sub, Dataproc, Cloud Composer, Bigtable, Spanner, Cloud Storage, Dataplex and Datastream.
  3. There are no prerequisites; Google recommends 3+ years of industry experience, including 1+ years designing and managing solutions on Google Cloud. The registration fee is US$200 (plus tax where applicable).
  4. Exam duration is 2 hours with 40–50 multiple choice and multiple select questions, online-proctored or at a test center, in English or Japanese. The certification is valid for 2 years.
  5. Google doesn’t publish a pass mark; this practice test uses 70% as the target.
  6. The five exam sections are weighted about 22%, 25%, 20%, 15% and 18%, so this test has 50 questions split 11 / 13 / 10 / 7 / 9.
  7. A shorter 1-hour, 20-question renewal exam (US$100) is available for holders inside the renewal window.
  8. Exam guide and certification page for more details.

Domain 1: Designing data processing systems (~22%)

A bank must store a BigQuery dataset encrypted with keys that its security team creates, rotates and can disable at any time to make the data unreadable. What should the data engineer configure?

⬜ Google’s default encryption at rest, which already applies AES-256 to every table
⬜ Customer-managed encryption keys (CMEK) in Cloud KMS for the dataset’s tables
⬜ Client-side encryption of every column before loading, with keys kept in a spreadsheet
⬜ A VPC Service Controls perimeter around the project

A streaming pipeline loads customer events containing email addresses into BigQuery. Analysts must be able to join events for the same customer, but must never see the real email address. Which approach meets both needs?

⬜ Replace every email with a new random UUID generated for each event as it arrives
⬜ Deterministic pseudonymization of the email with Sensitive Data Protection
⬜ Drop the email column entirely in the pipeline
⬜ Load the raw email and rely on analysts not querying the column

A company’s regulator requires that all new data resources for its EU business be created only in EU locations. What is the most effective way to enforce this across every project in the EU folder?

⬜ Ask every developer to always pass –location=EU in their commands and scripts
⬜ Create a Cloud Monitoring alert that fires whenever a resource is created outside an EU region
⬜ Grant the BigQuery Admin role only to EU-based employees
⬜ Set the gcp.resourceLocations organization policy on the EU folder

A healthcare company is worried that a user with valid credentials could copy BigQuery tables to a personal project outside the organization. Which control reduces this data exfiltration risk?

⬜ Firewall rules that block outbound port 443 traffic from every VM in the VPC network
⬜ A VPC Service Controls perimeter around the data projects
⬜ Customer-managed encryption keys on every table
⬜ Cloud Audit Logs Data Access logging

A data team wants developers to experiment freely with pipelines and schemas without any risk to production data, while keeping IAM simple. How should the environments be organized?

⬜ Use one project with datasets named dev_ and prod_ and trust the naming convention
⬜ Put development and production tables in the same dataset with different table prefixes
⬜ Give every developer the BigQuery Admin role on the production project
⬜ Separate dev and prod projects, each with its own datasets and IAM

An analytics team builds its BigQuery transformations as SQL in Dataform. It wants each run to automatically flag rows with null customer IDs or duplicate order IDs in the output tables. What should it add?

⬜ A Cloud Function that samples one row per table each day
⬜ Dataform assertions such as nonNull and uniqueKey in the table config
⬜ BigQuery table expiration on the output tables
⬜ A materialized view over each output table

A global payments application needs a relational database with strongly consistent ACID transactions across regions, horizontal scale and 99.999% availability. Which service fits?

⬜ Cloud SQL for PostgreSQL with read replicas in each region
⬜ Bigtable with replication across clusters
⬜ Spanner with a multi-region configuration
⬜ BigQuery with cross-region dataset replication

A retailer’s critical BigQuery datasets must keep serving queries and accept writes if its primary region suffers a complete outage, with an RPO of about 15 minutes. What should it use?

⬜ BigQuery managed disaster recovery with an Enterprise Plus failover reservation
⬜ Cross-region dataset replication alone, promoting the replica during the outage
⬜ Daily table snapshots stored in the same region
⬜ Exporting tables to a multi-region Cloud Storage bucket every week

Before migrating dozens of BigQuery tables into a new data platform, a data engineer wants column statistics such as null percentages, distinct values and value ranges, and suggested quality rules. Which feature provides this with the least effort?

⬜ Writing a SELECT COUNT(*) query for each column by hand
⬜ Cloud Monitoring dashboards for the BigQuery datasets
⬜ Dataplex data profiling scans
⬜ BigQuery INFORMATION_SCHEMA.JOBS

A company is migrating from Teradata to BigQuery and has thousands of SQL scripts. It wants to convert them to GoogleSQL in bulk and review the results. Which tool should it use?

⬜ Database Migration Service
⬜ Transfer Appliance
⬜ The BigQuery batch SQL translator
⬜ Storage Transfer Service

A media company must move 600 TB of archived video from its data center to Cloud Storage. Its internet link is 1 Gbps and already busy, and the migration must finish within a few weeks. What should it use?

⬜ Storage Transfer Service over the existing internet link
⬜ gcloud storage cp from a single on-premises server
⬜ Datastream
⬜ Transfer Appliance

Domain 2: Ingesting and processing the data (~25%)

A Dataflow streaming pipeline computes per-minute sales totals with fixed windows. Mobile devices sometimes send events up to 10 minutes late, and those events must still be counted in their correct window. What should the engineer configure?

⬜ Processing-time windows so each event is counted in the window in which it arrives
⬜ Allowed lateness of 10+ minutes on event-time windows, with late firings
⬜ A larger number of Dataflow workers
⬜ Discard every event that arrives after the watermark to keep results stable

An order system publishes status changes to Pub/Sub. The subscriber must receive the changes for each order in the order they were published, while different orders can be processed in parallel. What should be used?

⬜ A single subscriber with one thread for the whole subscription
⬜ Ordering keys set to the order ID, with message ordering enabled
⬜ A dead-letter topic
⬜ Exactly-once delivery without ordering

A few malformed messages keep failing in a Pub/Sub push subscriber and are redelivered endlessly, delaying other messages. How should the engineer handle them?

⬜ A dead-letter topic with a maximum number of delivery attempts
⬜ Increase the subscription’s acknowledgement deadline to the 10-minute maximum
⬜ Delete and recreate the subscription every day
⬜ Enable message ordering on the subscription

A company wants to replicate changes from its operational MySQL database into BigQuery with low latency for analytics, without writing or managing pipeline code. Which service should it use?

⬜ Datastream with BigQuery as the destination
⬜ Database Migration Service
⬜ A nightly mysqldump loaded with the bq command
⬜ BigQuery Data Transfer Service scheduled hourly

A team runs hundreds of existing Apache Spark and Hive jobs on an on-premises Hadoop cluster and wants to move them to Google Cloud with as few code changes as possible. Which service fits best?

⬜ Dataflow, rewriting each job in Apache Beam
⬜ Cloud Data Fusion
⬜ BigQuery scheduled queries
⬜ Dataproc

An e-commerce company has many producer and consumer applications written against Apache Kafka APIs. It wants to stop running Kafka brokers itself but keep using its existing Kafka client code. What should it choose?

⬜ Google Cloud Managed Service for Apache Kafka
⬜ Rewrite all clients to use Pub/Sub libraries
⬜ Bigtable
⬜ Cloud Tasks

A business analytics team with little coding experience needs to build ETL pipelines from SaaS apps and databases into BigQuery using a visual, drag-and-drop interface with prebuilt connectors. Which service should it use?

⬜ Cloud Data Fusion
⬜ Dataflow with the Apache Beam Java SDK
⬜ Dataproc with custom PySpark jobs
⬜ Cloud Run functions

Click events arrive in Pub/Sub as JSON that already matches the BigQuery table schema. No transformation is needed. What is the simplest way to land them in BigQuery?

⬜ A Dataflow streaming job that reads and writes each message
⬜ A Pub/Sub BigQuery subscription on the topic
⬜ A Cloud Run service that inserts rows one at a time
⬜ A daily export of the topic to Cloud Storage followed by a load job

A streaming Dataflow pipeline must classify each incoming support ticket with a trained PyTorch model before writing it to BigQuery, and the team wants to update the model without stopping the pipeline. What should it use?

⬜ A BigQuery scheduled query that classifies tickets once a day
⬜ Cloud Data Fusion’s Wrangler
⬜ A Dataproc cluster that polls BigQuery every hour
⬜ The Apache Beam RunInference transform

A nightly process must call three Google Cloud APIs in sequence: start a BigQuery job, wait for it, then call a Cloud Run service with the result. The team wants a serverless orchestrator with no environment to run. Which service fits best?

⬜ Cloud Composer
⬜ Workflows
⬜ A Compute Engine VM running cron
⬜ Pub/Sub with exactly-once delivery

A team wants to run the same Dataflow pipeline in dev, test and prod with different parameters, and have Cloud Build package each new version from Git automatically. What should it build?

⬜ A Compute Engine image that runs the pipeline from a cron job
⬜ One hard-coded pipeline per environment, deployed by hand
⬜ A Dataflow Flex Template built by Cloud Build
⬜ A BigQuery stored procedure

Security policy forbids external IP addresses on Dataflow worker VMs. The workers must still read from Pub/Sub and write to BigQuery. Which two actions are required? (select two)

⬜ Open TCP port 22 to the internet
⬜ Assign each worker a static external IP address
⬜ Enable Private Google Access on that subnetwork
⬜ Create a VPC peering connection to Google’s services network
⬜ Run the job with public IPs disabled (for example –no_use_public_ips) on a specified subnetwork

A streaming Dataflow job needs a code fix. The team must deploy the new version without losing in-flight data or reprocessing from scratch, and the transforms are compatible. What should it do?

⬜ Cancel the running job, then start the new version as a fresh job
⬜ Delete the Pub/Sub subscription and create a new one for the new job
⬜ Stop all publishers until the new version is running
⬜ Relaunch with the update option and the same job name

Domain 3: Storing the data (~20%)

An IoT platform writes millions of sensor readings per second and serves single-digit millisecond lookups of recent readings by device ID. Complex joins and SQL transactions aren’t needed. Which storage service fits best?

⬜ Bigtable
⬜ Cloud SQL for MySQL
⬜ BigQuery
⬜ Firestore

A Bigtable table stores sensor readings with the row key timestamp#device_id. Writes are slow and one node is overloaded. Which row key design fixes the problem?

⬜ timestamp#device_id with more nodes added
⬜ A row key made only of a sequential reading number
⬜ device_id#timestamp, so writes spread across devices
⬜ The current date as the row key, with each reading as a new column

A 50 TB BigQuery events table is queried mostly by event date and then filtered by customer_id. Costs are high because queries scan the full table. Which two changes reduce the bytes scanned? (select two)

⬜ Partition the table by the event date column and require a partition filter
⬜ Increase the time travel window to 7 days
⬜ Cluster the table by customer_id
⬜ Convert the table to an external table on Cloud Storage
⬜ Use SELECT * with LIMIT 100 to scan fewer rows

Log files in a Cloud Storage bucket are read often for 30 days, rarely for a year, and must then be deleted after 7 years. How should storage costs be managed with no manual work?

⬜ Lifecycle rules for class changes at 30 and 365 days and deletion at 7 years
⬜ Keep all files in Standard storage and have an operator delete old files by hand each year
⬜ Move the files to BigQuery long-term storage
⬜ Enable Object Versioning on the bucket

In BigQuery, an orders table and an order_items table are always queried together, and the join is expensive. The items are only ever read with their order. How should the data model change?

⬜ Normalize further into five smaller tables
⬜ Move the tables to Cloud SQL
⬜ Create a separate dataset for each table
⬜ Store items as a nested, repeated field in each order row

A data lake has Parquet files in Cloud Storage. Analysts query them from BigQuery, and the security team wants row-level and column-level security on that data without giving analysts direct access to the bucket. What should be used?

⬜ BigLake tables using a connection to read the bucket
⬜ Standard external tables with Storage Object Viewer granted to every analyst
⬜ Copy the files into a second bucket for each analyst team
⬜ Signed URLs for each Parquet file

A company has data spread across many Cloud Storage buckets and BigQuery datasets in several projects. It wants one place to organize them into logical domains, discover assets and apply consistent governance without moving the data. What should it use?

⬜ Copy all the data into one central BigQuery dataset
⬜ Cloud Data Fusion
⬜ Dataplex, cataloging the assets where they already are
⬜ A shared spreadsheet that lists every table

A large enterprise wants each business domain to own and publish its own data products, while a central team provides the shared platform and sets organization-wide governance policies. Which architecture does this describe?

⬜ A data mesh with federated data governance
⬜ A single centralized data warehouse owned by one team
⬜ A Lambda architecture
⬜ A star schema

An application team needs a PostgreSQL-compatible database for heavy transactional traffic, and the business also wants fast analytical queries on the same live data without an ETL pipeline. Which service fits best?

⬜ Cloud SQL for MySQL with a read replica for reporting
⬜ Memorystore for Redis
⬜ Firestore in Datastore mode
⬜ AlloyDB for PostgreSQL with the columnar engine

A staging dataset in BigQuery holds temporary tables created by daily jobs, and they are often forgotten and keep costing money. What is the simplest way to clean them up automatically?

⬜ Enable the long-term storage discount
⬜ Reduce the time travel window to 2 days
⬜ Set a default table expiration on the staging dataset
⬜ Schedule a weekly manual review

Domain 4: Preparing and using data for analysis (~15%)

Executives use Looker Studio dashboards on BigQuery tables, and filters take several seconds to respond. The team wants sub-second interactive performance without changing the dashboards’ SQL. What should it enable?

⬜ Batch query priority
⬜ A larger time travel window
⬜ Exporting the tables to CSV for the dashboards
⬜ BigQuery BI Engine

Many reports run the same aggregation of daily revenue by store over a large, frequently updated sales table. The team wants faster, cheaper queries that always return current data. What should it create?

⬜ A logical view with the aggregation
⬜ A materialized view with the aggregation
⬜ A scheduled query that rewrites a summary table once a week
⬜ A copy of the table in another region

A BigQuery table has a national ID column. Support analysts must see only a masked version, while the fraud team must see the real value, all querying the same table. Which two steps are required? (select two)

⬜ Grant support analysts BigQuery Data Viewer on the project only
⬜ Grant the fraud team the Fine-Grained Reader role on the policy tag
⬜ Attach a policy tag with a data masking policy to the column and grant support analysts the Masked Reader role
⬜ Encrypt the column with a key only the fraud team knows
⬜ Create a separate copy of the table without the column for support

A BigQuery query that joins two large tables became slow after data growth. The engineer wants to see which stage spends the most time and whether data is skewed across workers. Where should they look?

⬜ The Cloud Storage bucket’s lifecycle rules
⬜ The query plan in the job’s execution details
⬜ The Pub/Sub subscription’s backlog and delivery-latency metrics
⬜ The dataset’s IAM policy

A data team trains a BigQuery ML model and wants the same feature preprocessing, such as scaling and bucketizing, to be applied automatically when the model is used for prediction. What should it use?

⬜ The TRANSFORM clause in the CREATE MODEL statement
⬜ A separate preprocessing query copied into every prediction query
⬜ A Dataproc job that preprocesses data before each prediction
⬜ Column-level security

A company wants to build a retrieval-augmented generation (RAG) assistant over thousands of product manuals already loaded as text chunks in BigQuery, without moving the data to another system. What should it do?

⬜ Use LIKE ‘%keyword%’ filters only
⬜ Export the chunks to Memorystore for full-text search
⬜ AI.GENERATE_EMBEDDING with VECTOR_SEARCH, both in BigQuery
⬜ Store the manuals in Bigtable

A retailer wants to share live sales datasets with 40 supplier organizations. Suppliers must query the data in their own projects, without copies being made, and the retailer must be able to stop them exporting it. What should it use?

⬜ Weekly CSV exports emailed to each supplier
⬜ Grant each supplier’s users the BigQuery Admin role
⬜ BigQuery sharing (Analytics Hub) listings with egress controls
⬜ Copy the datasets into each supplier’s own project every night

Domain 5: Maintaining and automating data workloads (~18%)

A team runs Spark jobs on Dataproc for two hours each night. The cluster sits idle the rest of the day, and all data is stored in Cloud Storage. How should it cut costs?

⬜ Keep the persistent cluster running but add more preemptible worker nodes
⬜ Store the data in HDFS on the cluster’s persistent disks for speed
⬜ Job-scoped clusters created per run, or serverless Spark
⬜ Switch to a larger machine type for the master node

A Cloud Composer environment slows down because one DAG task loads a 20 GB file into pandas on the Airflow worker and transforms it. What is the recommended fix?

⬜ Increase the DAG parsing interval
⬜ Delegate the heavy work to BigQuery, Dataflow or a separate pod
⬜ Combine all of the DAG’s steps into one large PythonOperator task
⬜ Disable retries on the task

An Airflow DAG loads each day’s files into a BigQuery date partition. When a run is retried or backfilled, rows get duplicated. How should the task be redesigned?

⬜ Append to the table on every run and deduplicate once a year
⬜ Make the task idempotent by overwriting only the run’s date partition
⬜ Set the DAG’s start_date to datetime.now()
⬜ Turn off catchup and never backfill

Month-end finance reports in BigQuery must always have guaranteed compute capacity, even when data scientists run large ad hoc queries in other projects. How should capacity be managed?

⬜ Keep every project on on-demand pricing and let BigQuery share capacity
⬜ Run the finance reports as batch priority queries at month-end
⬜ Increase the finance project’s custom query quota for the month
⬜ An Editions reservation with baseline slots for finance

A team runs hundreds of non-urgent report queries every night on on-demand BigQuery and doesn’t mind if they wait. Interactive users complain that their queries are slow or queued during that time. Which change helps?

⬜ Run them with batch priority
⬜ Run the nightly queries with interactive priority
⬜ Use SELECT * in the nightly queries
⬜ Move the nightly queries to Cloud SQL

A BigQuery bill doubled this month. The data engineer wants to find which users and queries processed the most bytes over the last 30 days using SQL. Where should they look?

⬜ The Cloud Storage access logs
⬜ The table’s partition metadata
⬜ INFORMATION_SCHEMA.JOBS
⬜ The Pub/Sub topic’s metrics

On on-demand pricing, a company wants to prevent any single analyst from processing more than 2 TB of data per day in a project, to avoid surprise bills. What should it configure?

⬜ A BigQuery reservation with autoscaling
⬜ A Cloud Storage lifecycle rule
⬜ Table clustering on every table
⬜ A per-user daily query usage custom quota

An order database runs on Cloud SQL for PostgreSQL. It must survive a zone failure with automatic failover, and the team also wants a copy in another region for disaster recovery. What should it configure?

⬜ A single-zone instance with automated daily backups and point-in-time recovery
⬜ Two independent instances in the same zone
⬜ A regional HA instance plus a cross-region read replica
⬜ A Memorystore cache in front of the database

A faulty job overwrote rows in a production BigQuery table 3 hours ago. The team needs the table back as it was just before the job, as quickly as possible. What should it do?

⬜ Use time travel to copy the table as of before the job
⬜ Open a support case and ask Google to restore it from fail-safe storage
⬜ Restore from last month’s export of the table in Cloud Storage
⬜ Re-run all of the year’s pipelines to rebuild the table from scratch
